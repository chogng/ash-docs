# 会话与任务

会话保存你的消息、Agent 回复、工具活动和执行状态。一个会话可以连续处理多轮相关工作。本页说明何时继续、何时新建，以及任务运行中如何补充要求。

本文介绍 Ash Agent 会话。桌面侧栏中的 **ChatGPT** 使用另一组会话历史、项目和草稿，见[使用 ChatGPT](/docs/agents/chatgpt.md)。Agent 的排队、分支和 `/compact` 操作不适用于该输入区。

桌面操作依据当前主分支实现，已发布安装包的功能以实际版本为准。需要运行对应源码时，见[从源码运行](/docs/getstarted/run-from-source.md)。

## 创建或恢复会话

| 操作 | 桌面工作台 | Ash Code 终端界面 |
| --- | --- | --- |
| 新建 | 在聊天输入框输入 `/new` | 输入 `/new`；`/new <名称>` 用参数命名新会话，之后另行发送任务 |
| 查看历史 | 输入 `/history`，选择已有会话 | 输入 `/resume`，从已保存会话中选择 |
| 恢复指定会话 | 从历史列表选择 | 输入 `/resume <session-id>` |

要在同一会话中另起空白对话，先打开已有对话，再从聊天操作菜单或命令面板选择 **在会话中新增聊天**（**New Chat in Session**）。它创建同会话中的空聊天，不复制历史，也不会自动发送任务。原对话仍保留；尚未发送过消息的新建草稿不能作为此操作的目标。

恢复会话后，先查看最后一轮的状态、工具结果和待发送队列，再继续提交要求。重新打开会话不会重跑已经结束的任务，但已被接受的排队消息仍可能继续执行。

Ash Code 中，`/new`、`/resume`、`/branch` 等本地会话命令在任务运行时不可用。先等待当前轮结束，或中断后再执行。`/new <名称>` 只创建和命名会话，不会自动把名称作为任务执行。

## 重命名、归档和删除会话

工作台中的新对话会使用首条消息生成初始名称。需要更明确的名称时，先打开目标对话，再从命令面板选择：

* **聊天: 重命名对话**（**Chat: Rename Conversation**）：修改当前对话的名称。
* **聊天: 重命名会话**（**Chat: Rename Session**）：修改整个会话的名称。会话名称由其根对话决定，修改根对话名称也会更新会话名称。

名称去除首尾空白后须为 1 到 256 个字符。按 `Enter` 保存，按 `Esc` 取消。名称会保存在会话历史中，并更新连接同一服务的其他窗口；迟到的自动命名不会覆盖手动名称。重命名不会创建新会话，也不改变已有对话内容。

暂时不再需要的会话可以通过对话菜单归档。归档会中断其中运行的工作，之后仍可恢复根对话。只有已归档的会话才能通过以下入口永久删除：

1. 在命令面板运行 **聊天: 删除已归档会话**（**Chat: Delete Archived Session**）。
2. 按名称选择要删除的会话。使用键盘时，用方向键选择，再按 `Enter`。
3. 核对确认框中的会话名称和影响，确实不再需要时选择 **永久删除**（**Delete permanently**）。按 `Esc` 可以取消。

永久删除会移除整个会话及其对话历史，无法撤销；该会话中后来恢复运行的工作也会停止。其他会话和未发送草稿会保留。需要留存的结果应在删除前另行保存。

## 选择继续还是新建

继续当前会话适合修正同一组改动、补充验收条件、解释失败原因，或完成紧密相关的下一步。

当新任务涉及不同项目或无关目标时，创建新会话。这样能减少无关上下文，也更容易检查每项工作的结果。创建新会话本身不会撤销原会话产生的文件改动。

需要定期执行同一类任务时，使用[自动化任务](/docs/agents/automations.md)，并在每次运行后检查结果。

## 编辑已发送的请求

在编辑器窗口或 Agents 窗口的 **Chat**、**Code** 中，可以修改带有 **编辑消息**（**Edit message**）操作的已接受请求。运行中追加的补充消息不提供同一编辑入口。

1. 找到要修改的请求，选择 **编辑消息**。
2. 在 **编辑请求**（**Edit request**）中修改文本。按 `Enter` 换行。
3. 选择 **发送编辑后的请求**（**Send edited request**），或按 `Ctrl+Enter`（macOS：`Cmd+Enter`）提交。

提交会从该请求之前的历史位置创建同会话中的新对话，并执行修改后的请求。原请求中已接受的上下文、图片和音频保留；该轮后来的补充输入和工具输出不会随修改后的请求重放。原对话仍可查看，在当前窗口切回原对话也可以继续原来的未发送草稿。

发送前选择 **取消编辑**（**Cancel edit**）或按 `Esc`，原请求和输入框草稿不变。发送失败时，编辑框保留修改内容并显示错误；先检查错误，再重试。

编辑需要原请求之前的文件检查点。绑定普通非 Git 目录的对话当前不支持此操作；Git 项目缺少完整检查点时也会失败。旧历史缺少原始提交标识时，也可能提示请求无法编辑。此时可以继续原对话发送修正要求，或新建对话并提供必要背景。

编辑会发起一次新的执行，不会撤销原对话已经发生的文件修改或外部操作。提交前检查原任务结果，避免重复执行外部写入。

## 运行中补充要求或排队

先分清这条消息是要改变当前任务，还是等它结束后再做。

| 场景 | 操作 | 结果 |
| --- | --- | --- |
| 工作台当前任务可接收补充输入，模式未变，也未选择新 Skill | 发送消息 | 补充当前任务 |
| 工作台切换模式或选择 Skill 后，当前任务仍未结束 | 发送消息 | 排队为新一轮，保留当前任务的设置 |
| Ash Code 任务运行中 | 按 `Enter` | 消息进入队列，等当前任务结束后执行 |
| Ash Code 任务运行中，模式未变且草稿没有 Skill 选择 | 按 `Ctrl+Enter` | 单次补充当前任务 |
| Ash Code 已切换任务模式 | 提交补充消息 | 按新模式排队，不改变当前任务 |
| 当前任务等待批准或回答 | 使用对应交互面板 | 回答正在等待的请求 |

补全列表打开时，`Enter` 或 `Tab` 先处理候选。Ash Code 中，带 Skill 的草稿不能用 `Ctrl+Enter` 补充当前轮；保留草稿并按 `Enter` 排队，或等当前轮结束。

已被服务端接受的队列会持久保存；尚未成功提交的本地草稿与已接受的排队消息不同。连接中断后，先恢复会话、核对队列和记录，不要直接重新发送同一任务。队列是否可用也取决于当前服务端是否启用了这项能力。

补充要求时，明确说明保留和停止的范围：

```prompt
保留刚才的数据模型改动，停止界面修改，先补齐单元测试。
```

补充消息只增加输入，不能把当前任务换成另一模型、模式、Skill 或工具选择。工作台中改选模型或推理强度，作用于后续新一轮。已经发生的文件写入和外部操作不会因新消息而撤销。

### 编辑 Ash Code 的待发送队列

在输入框中按 `Alt+↑` 聚焦队列，再用方向键选中消息：

* `Enter`：暂停该条排队消息并恢复到输入框编辑。先清空输入框里的其他草稿；重新排队会替换原条目。
* `Ctrl+Enter`：请求立即发送。当前轮可接收补充输入时，会尝试作为补充发送；模式等条件仍需匹配。
* `Ctrl+↑` / `Ctrl+↓`：调整顺序。
* `Delete`：移除排队消息。
* `Esc`：返回输入框。

队列中的发送、暂停和编辑需要服务端确认。看到发送失败或仍在发送的状态时，先检查错误，不要重复追加同一条消息。取消排队消息不会撤销已经执行的任务。

## 停止任务并继续

工作台使用输入区的 **Stop（停止）**。Ash Code 默认按 `Esc` 中断当前任务；弹窗、补全或自定义回答编辑器打开时，`Esc` 会先退出当前交互。自定义按键以 `/shortcuts` 显示的绑定为准。

1. 如果在 Ash Code 中连后续任务也不想执行，先移除不再需要的排队消息。
2. 请求停止后，等待任务退出“取消中”状态。
3. 检查最后的工具结果和实际文件改动，确认哪些步骤已经完成。
4. 发送新的要求，明确要继续、修正或放弃的部分。

停止当前轮不等于清空队列，已排队的下一轮仍可能启动。停止也不会自动回滚文件或外部操作。不要把关闭聊天页面或连接中断当作停止成功。

## 理解任务状态

| 状态 | 你可以做什么 |
| --- | --- |
| 已创建、尚未运行 | 等待启动；不要把它当作可补充输入的运行中任务 |
| 运行中 | 查看工具活动，补充要求或停止 |
| 等待批准 | 检查动作和目标，批准一次或拒绝 |
| 等待回答 | 提供 Agent 或工具需要的信息 |
| 等待能力可用 | 查看缺少的执行能力或连接，按提示恢复；此时不能直接补充当前轮 |
| 取消中 | 等待停止结果，避免重复提交 |
| 已完成、失败或已中断 | 检查记录，决定下一轮如何继续 |

界面暂时断线时，不要把没有新输出当作执行失败。恢复连接后，以重新加载的记录为准。显示执行结果未知时，先检查实际文件或外部状态，再决定是否重新执行。

## 恢复 Agent Host 连接

工作台会尝试恢复中断的 Agent Host 连接。桌面电脑休眠时暂停恢复尝试，唤醒后继续处理，不会把休眠时间算作持续重试失败。

如果通知显示无法重新连接到 Agent Host，先检查网络或服务是否恢复，再选择通知中的 **重新连接**（**Reconnect**），也可以从命令面板运行 **Agent Host: 重新连接**（**Agent Host: Reconnect**）。使用键盘时，按 `Tab` 聚焦通知按钮，再按 `Enter` 或空格。

重新连接会恢复连接和已保存状态，不会自动重发结果未确认的消息或写入请求。连接恢复后，先核对会话记录、队列以及实际文件或外部结果，再决定是否重试。

如果提示 Web 授权已过期、被撤销或工作区已改变，需要打开新的授权链接；反复重连不能恢复已失效的授权。SSH 主机本身断线时，另见 [SSH 连接恢复](/docs/remote/ssh.md#退出和恢复连接)。

## 任务失败后如何处理

先读错误提示，再决定重试、改配置还是换一条做法。

| 情况 | 下一步 |
| --- | --- |
| 最新一轮失败，且显示 **Try again** | 确认已有操作后重试；只有最新且标记为可重试的失败轮可用 |
| 身份验证、模型配置或账号额度错误 | 修复登录与配置，或选择可用模型后再发消息 |
| 上下文达到上限 | 缩小请求，或新建会话并提供必要背景 |
| 同一工具反复失败 | 提供修正后的路径或条件，让 Agent 改用另一条可行方法 |
| 保存失败、断线或执行结果未知 | 先核对会话记录和实际文件或外部状态，再决定是否重试 |

工作台的 **Try again** 会在当前会话中发起新的继续请求，不是回滚并原样重放失败轮。此前已发生的改动仍在；涉及外部写入时尤其要防止重复操作。

## 从已有对话分出另一条思路

### 桌面工作台

先打开要复制的对话，再从聊天操作菜单或命令面板选择 **分叉对话**（**Fork Conversation**）。它复制当前已保存的历史，不会自动发送新消息，原对话仍保留。

| 所在窗口 | 分叉结果 |
| --- | --- |
| 编辑器窗口 | 创建独立会话并打开其中的新对话 |
| Agents 窗口的 **Chat** 或 **Code** | 在当前会话中创建新对话，并保留当前布局 |

需要从完整执行结果继续时，先等待当前轮结束再分叉。Git 项目的分叉需要对应历史位置的已封存文件检查点；提示检查点不可用时，先等待保存完成或检查错误。只想在同会话另起空白聊天时，使用 **在会话中新增聊天**。

### Ash Code

当前轮结束后，Ash Code 提供以下入口：

| 命令 | 行为 |
| --- | --- |
| `/branch <名称>` | 复制当前对话并切换到新分支 |
| `/fork` | 复制到独立会话，保留当前会话，等待新会话的输入 |
| `/fork <提示语>` | 复制到独立会话，在后台执行指定提示语 |

Fork 的结果不会自动回传到原会话，需要打开新会话查看。这里的分支名称是对话名称，不会自动创建同名 Git 分支。

分叉产生的新 Thread 使用独立执行目录：Git 项目使用受管 worktree，非 Git 项目复制父 Thread 当时的目录内容。Git 副本从父对话对应历史位置的封存检查点开始。独立执行目录仍可能绑定同一 Git 提交目标分支，提交前应核对目标。

## 压缩长对话

在工作台中，当前轮结束后，在聊天输入框执行：

```text
/compact
```

Ash 会发起独立的上下文压缩，并在会话中记录结果。后续模型请求使用摘要和保留的记录。压缩不能保证保留全部原文，精确核对仍应重新读取源文件或日志。

需要保留重点时，可以输入 `/compact <保留要求>`，例如说明要保留的验收条件和未完成事项。

当前 Ash Code 的 `/compact` 尚未接入同一手动压缩操作，不要把命令出现在补全列表或模型回复当作压缩成功；需要手动压缩时，请使用工作台。

如果想先检查已有结论，可以使用 `/advisor <问题>` 获取第二意见。手动咨询后等待你的下一步要求，完整行为见 [Advisor 顾问](/docs/agents/advisor.md)。

## 检查当前对话的文件更改

在 Git 项目中，桌面聊天输入框上方的文件数与增删行数可以打开文件比较。先确认当前入口的范围：

| 所在位置 | 统计和比较的范围 |
| --- | --- |
| **New Chat** | 当前工作区的 Git 更改，合并多个仓库的结果；需要 Git 扩展提供数据 |
| 已创建的对话 | 当前 Thread 从初始目录快照到当前有效检查点的净变更 |

对话中的统计不是各轮修改量的累加。同一个文件反复修改，只计算最后留下的差异；改回起点后不再计入。撤销或重做后，统计跟随恢复的文件检查点。回退后继续执行，只汇总当前历史路径；提交也不会清空这份对话历史变更。

1. 选择要检查的对话，再选择输入框上方的更改入口。
2. 在 **Conversation Changes** 中查看只读比较。它保留打开时的检查点内容，之后的工作文件修改不会替换其中的文本。
3. 需要检查后续结果时，重新打开更改入口。若提示加载期间对话已变化，重新打开以获取当前检查点。

没有净变更时，对话中的入口隐藏，不改为显示整个工作区的更改。看到 **Changes unavailable** 时，重新打开更改入口重试；读取失败不表示没有更改。

工作区统计中的行数带 `*` 时，表示部分文件无法按文本比较。这些文件仍计入文件数，但不计入增删行数；二进制或过大的内容也不能当作完整文本差异审阅。

这个入口用于复查净变更。需要按执行轮选择文件和提交时，使用会话的 **Changes**；需要暂存或提交工作区文件时，使用 [Git 侧栏](/docs/sourcecontrol/overview.md)。

## 复查执行过程

在 Agents 窗口中打开要检查的 Agent 会话，再从对话菜单或命令面板选择：

* **显示 Agent 输出**（**Show Agent Output**）：在输出面板阅读该会话的模型、工具和子任务执行摘要。选择记录中的链接，可以定位对应的调试日志事件。
* **显示 Agent 调试日志**（**Show Agent Debug Logs**）：打开当前 Thread 的已保存执行历史，检查事件、工具结果和已记录的模型输入。

输出通道名称标明正在查看的会话。切换聊天不会自动替换正在复查的输出；需要时再次运行**显示 Agent 输出**。清空输出只清理文本视图，不删除已保存的调试日志，也不停止任务。

完整步骤见[查看 Agent 调试日志](/docs/agents/trace.md)。查看记录不会重跑任务；未记录的详细正文也不能事后补回。
