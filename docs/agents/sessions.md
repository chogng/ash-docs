# 会话与任务

会话保存你的消息、Agent 回复、工具活动和执行状态。一个会话可以连续处理多轮相关工作。本页说明何时继续、何时新建，以及任务运行中如何补充要求。

## 创建或恢复会话

| 操作 | 桌面工作台 | Ash Code 终端界面 |
| --- | --- | --- |
| 新建 | 在聊天输入框输入 `/new` | 输入 `/new`，也可以使用 `/new <提示语>` |
| 查看历史 | 输入 `/history`，选择已有会话 | 输入 `/resume`，从已保存会话中选择 |
| 恢复指定会话 | 从历史列表选择 | 输入 `/resume <session-id>` |

恢复会话后，先查看最后一轮的状态和工具结果，再继续提交要求。重新打开会话不会重跑已经结束的任务。

## 选择继续还是新建

继续当前会话适合修正同一组改动、补充验收条件、解释失败原因，或完成紧密相关的下一步。

当新任务涉及不同项目或无关目标时，创建新会话。这样能减少无关上下文，也更容易检查每项工作的结果。创建新会话本身不会撤销原会话产生的文件改动。

## 运行中补充要求或排队

| 场景 | 操作 | 结果 |
| --- | --- | --- |
| 桌面工作台的任务可以接收补充输入时 | 发送消息 | 补充当前任务 |
| Ash Code 任务运行中 | 按 `Enter` | 把草稿排队，当前任务结束后再提交 |
| Ash Code 任务运行中 | 按 `Ctrl+Enter` | 单次补充当前任务 |
| 当前任务等待批准或回答 | 使用对应交互面板 | 回答正在等待的请求 |

补全列表打开时，`Enter` 或 `Tab` 先处理候选。Ash Code 的待发送队列保留在当前客户端中；查看状态时，要区分尚未提交的草稿和后端已接受的任务。

补充要求时，明确说明保留和停止的范围：

```prompt
保留刚才的数据模型改动，停止界面修改，先补齐单元测试。
```

新消息不会撤销已经发生的写入或外部操作。需要立即中止时，使用当前任务的停止操作，再检查已经完成的工具结果。运行中补充输入也不能换用另一项 Skill；选择 Skill 需要开始新一轮。

## 理解任务状态

| 状态 | 你可以做什么 |
| --- | --- |
| 运行中 | 查看工具活动，补充要求或停止 |
| 等待批准 | 检查动作和目标，批准一次或拒绝 |
| 等待回答 | 提供 Agent 或工具需要的信息 |
| 取消中 | 等待停止结果，避免重复提交 |
| 已完成、失败或已中断 | 检查记录，决定下一轮如何继续 |

界面暂时断线时，不要把没有新输出当作执行失败。恢复连接后，以重新加载的记录为准。显示执行结果未知时，先检查实际文件或外部状态，再决定是否重新执行。

## 从已有对话分出另一条思路

Ash Code 提供两种入口：

| 命令 | 行为 |
| --- | --- |
| `/branch <名称>` | 复制当前对话并切换到新分支 |
| `/fork` | 复制到独立会话，保留当前会话，等待新会话的输入 |
| `/fork <提示语>` | 复制到独立会话，在后台执行指定提示语 |

Fork 的结果不会自动回传到原会话，需要打开新会话查看。对话分支不代表自动创建 Git 分支或隔离文件工作区；并行修改前先确认两个会话的工作目录。

## 压缩长对话

当前轮结束后，在聊天输入框执行：

```text
/compact
```

Ash 会发起独立的上下文压缩，并在会话中记录结果。后续模型请求使用摘要和保留的记录。压缩不能保证保留全部原文，精确核对仍应重新读取源文件或日志。

如果想先检查已有结论，可以使用 `/advisor ask <问题>` 获取第二意见。手动咨询后等待你的下一步要求，完整行为见 [Advisor 顾问](/docs/agents/advisor.md)。
