# 使用 Advisor 获取第二意见

Advisor 让 Ash 向单独选择的模型咨询。主模型负责推进任务，顾问根据已有对话检查假设、比较方案并指出缺少的证据。启用顾问后可以由主模型按需咨询，也可以输入 `/advisor <问题>` 立即提问。

## 什么时候咨询最有用

* 准备重构时，确认方案有没有遗漏依赖或约束。
* 同一个测试反复失败时，检查当前解释是否成立。
* 准备结束任务时，检查现有测试是否覆盖关键风险。

先让主模型读到相关代码和测试结果，再提出一个具体问题。例如，“取消保存后是否还有写入可能，缺哪条测试”，比“重新检查整个项目”更容易得到可验证的建议。

顾问没有工具，不能自行搜索文件、修改代码或运行测试。它的建议需要由主模型或你继续验证。

## 选择模型并启用

先连接后端，配置所需的[模型与账号](/docs/configure/models.md)。顾问选择独立于主模型，不会替换当前工作的模型。

### 桌面工作台

1. 在聊天输入框输入 `/advisor`，打开顾问配置入口。
2. 选择可用模型。选择模型会启用顾问，配置立即保存。
3. 如暂时不用，关闭顾问开关；已选模型会保留。

也可以在设置中的 **Advisor** 项检查所选模型和启用状态。模型下拉菜单的显示范围可能受模型可见性影响；菜单中隐藏模型不会自动清除已保存的选择。

### Ash Code 终端界面

1. 输入 `/advisor`，或进入“配置 → 通用 → 顾问”。
2. 选择顾问模型。
3. 检查启用开关。首次在终端配置页选择模型时仍保持关闭，需要显式开启。

终端的“提供商”页面用于管理供应商，顾问开关与模型选择位于“通用”。

### 直接指定模型

两个界面都支持：

```text
/advisor <provider>/<model>
```

请替换为可用模型的完整标识。这个命令同时选择并启用顾问，与终端配置页首次选模型的行为不同。

以上配置保存为当前 Ash 配置目录的全局顾问设置，后续使用同一配置目录的会话会受影响。选择模型、关闭或清除配置本身不会发起咨询，也不需要先创建一个任务。

## 直接咨询一次

等待当前轮结束，在聊天输入框输入问题：

```text
/advisor 根据刚才读取的保存逻辑和测试结果，取消保存后是否还可能写入文件？请指出缺少的验证。
```

Ash 直接调用已启用的全局顾问模型，不先请求主模型决定是否咨询。咨询结束后显示建议，等待你的下一步要求，不自动修改代码，也不触发目标自动续跑。

需要继续实现时，再发一条普通消息，例如：

```prompt
请验证顾问提到的取消竞态；如果确实存在，再给出最小修复并运行相关测试。
```

问题应直接跟在 `/advisor` 后，不需要 `ask` 子命令。要补充文件或附件，先把材料加入正常对话，再咨询。终端直接咨询入口只接受文本问题。

## 让主模型在任务中咨询

启用顾问后，主模型可以调用 `advisor` 工具，但并不保证每轮都会调用。你可以说明希望检查的具体决策：

```prompt
调查保存操作被取消后仍写入文件的问题。请先读相关代码和测试，确定修复方案前咨询 Advisor，重点检查取消信号是否覆盖整个写入过程，再实现并验证。
```

主模型收到建议后会继续处理任务。顾问建议不是完成证明；主模型仍需读取必要的代码、运行测试并报告结果。

普通任务和直接咨询都会遵循当前的[权限与批准](/docs/configure/permissions.md)。顾问的建议不能授予执行权限。

## 顾问能看到哪些内容

每次咨询使用开始时固定的对话证据，包括问题、任务指令、消息，以及已经完成的工具调用和结果。对话中的代码、输出和附件可能因此发送给你选择的顾问供应商。咨询前应确认这些材料适合交给该供应商处理。

* 顾问不会自行扫描整个工作区。
* 尚未完成的工具调用不会作为完整的调用与结果发送。
* 如果对话已经压缩，沿用已有摘要和保留记录，不保证看到压缩前的全部原文。
* 咨询开始后的新消息、工具结果和文件变化不会补入本次请求。
* 剩余上下文仍超过顾问容量时会返回错误，不会为了这次咨询再次自动压缩，也不会自动换模型。

顾问不能递归调用顾问。证据不足时，应补充材料后再问，不要把推测当成已验证事实。

## 阅读建议与用量

桌面工作台将调用与结果显示为 **Advisor** 卡片。展开后可查看建议和返回的模型、问题、对话序列及用量信息。终端界面会在工具结果中展示建议。

顾问咨询有独立的模型用量。用量与参考费用计入本轮、线程以及已有目标的预算，但不改变主模型的上下文占用显示。供应商没有返回用量时保留未知状态，不能把它当作零费用。

| 项目 | 默认限制 |
| --- | --- |
| 每轮咨询次数 | 最多 3 次 |
| 每次咨询输出 | 最多 2048 token |
| 问题长度 | 非空，最多 8000 字节；中文字符可能占多个字节 |

次数和输出预算可以通过配置调整；这里列的是默认值。一次直接咨询单独开始一轮，只咨询一次。顾问拒答、达到上限或模型错误时，应阅读结果状态，不要仅凭存在卡片就认定咨询成功。

## 暂停、清除与配置生效

| 命令 | 作用 |
| --- | --- |
| `/advisor` | 打开顾问配置入口 |
| `/advisor <provider>/<model>` | 保存并启用全局顾问模型 |
| `/advisor <问题>` | 使用已启用的全局顾问模型直接咨询一次 |
| `/advisor off` | 关闭全局顾问，保留已选模型和预算 |
| `/advisor clear` | 清除全局顾问配置 |

当前不需要 `/advisor save` 或 `/advisor default`。它们不是当前的配置子命令，可能被当作问题发起咨询。`off`、`clear` 和没有空格的 `provider/model` 会优先按配置命令解析；例如只写 `/advisor src/app.ts` 会被识别成模型选择，应该改成 `/advisor 检查 src/app.ts 的取消逻辑`。

每轮开始时会固定顾问配置。中途换模型或关闭开关，不会改掉已经开始的咨询；需要中止时使用当前任务的停止操作。

直接咨询总是使用全局设置。旧会话可能保留单独的普通任务顾问选择，但全局关闭优先，且不改变直接咨询使用全局模型的规则。子 Agent 不自动启用顾问。

## 排查咨询问题

| 现象 | 处理方式 |
| --- | --- |
| 提示顾问未配置或关闭 | 用 `/advisor` 检查模型及启用开关；终端首次选模型后还要开启 |
| 指定的模型不可用 | 从列表重新选择，核对供应商标识、模型标识和有效凭据 |
| 当前轮仍在运行 | 等待完成或停止，再直接咨询 |
| 主模型没有咨询 | 启用只提供可用工具；在任务中写清希望咨询的具体问题 |
| 达到调用次数上限 | 使用已有建议继续，必要时在下一轮重新咨询 |
| 上下文超出顾问容量 | 选择容量更大的可用模型；在桌面工作台也可等当前轮结束后使用 `/compact` |
| 顾问缺少证据 | 先让主模型读取相关文件或测试输出，再问具体问题 |
| 身份验证或模型请求失败 | 检查所选供应商的配置与连接；不会在失败后自动换模型 |
| 恢复后结果未知 | 检查已有记录，再决定是否重问；已开始且结果未知的请求不会自动重发 |
