# 查看执行 Trace

执行 Trace 把一段对话已保存的执行记录组织成 Thread、Turn 和事件。你可以用它检查任务在哪一步失败、模型收到哪些已记录输入，以及工具或子任务的结果如何关联。本文带你打开一段真实会话的 Trace，再导出并离线复查。

本文适用于 Ash 的 Workbench 工作台和 Agents 窗口。执行 Trace 以编辑器打开，入口位于命令面板和 Agents 窗口的对话菜单。当前界面没有独立的 Trace 活动栏按钮或侧栏。查看记录不会重跑任务。

## 先查看 Agent 输出摘要

需要快速确认任务卡在哪一步时，先使用 Agents 窗口的输出面板：

1. 打开要检查的 Agent 会话。
2. 从对话菜单或命令面板选择**显示 Agent 输出**（**Show Agent Output**，`sessions.trace.showOutput`）。
3. 核对输出通道名称中的会话标题和 ID，查看模型、工具、子任务、失败或取消记录。
4. 选择记录中的执行链接，在 Trace 编辑器中定位对应的 Thread、Turn 和事件。

Agent 输出是有容量限制的执行摘要，不加载请求与响应正文。需要正文或事件关系时，继续使用执行 Trace。

切换聊天不会自动替换正在查看的输出。要改看新会话，再次运行**显示 Agent 输出**。只有输出面板可见且选中了 Agent 通道时，摘要才继续读取新记录。

清空输出只清理文本视图，保留已保存的 Trace，也不会重新回放已清除的旧记录。自动滚动只控制是否跟随新输出，不控制任务执行或记录开关。

## 打开当前对话的 Trace

1. 在 Agents 窗口打开要检查的已保存会话，选择相应的 Thread。
2. 打开命令面板，执行 **查看执行 Trace**（英文为 **View Execution Trace**，命令 ID 为 `sessions.trace.open`）。也可以从当前对话菜单选择同名操作。
3. 等待状态显示 **实时 · 已保存的执行历史**。查看器会定位当前 Thread 的最新已记录 Turn；有定位信息时，页面显示 **已定位…**。
4. 在执行树中展开 Thread 和 Turn，选择一个事件。右侧默认显示**概览**。

如果没有当前会话，这个命令会打开离线导入页。若指定的位置没有对应的已保存事件，页面会明确提示未找到，不会拿另一个事件代替。

### 恢复上次复查的位置

在命令面板中，根据需要选择入口：

| 位置与目的 | 命令 | 行为 |
| --- | --- | --- |
| Agents 窗口：查看当前聊天 | **查看执行 Trace**，`sessions.trace.open` | 定位当前会话、Thread 和最新已记录 Turn。 |
| Agents 窗口：继续上次复查 | **Trace**，`sessions.open.trace` | 恢复上次查看的位置；没有保存位置时使用当前会话。 |
| Agents 窗口：打开捕获文件 | **打开离线捕获**，`sessions.trace.import` | 打开导入页。 |
| Workbench：继续上次复查 | **恢复执行 Trace**，`ash.agentTrace.resume` | 恢复有效的保存位置；没有保存位置时打开导入页。 |
| Workbench：打开捕获文件 | **开发人员：打开执行 Trace**，`ash.agentTrace.open` | 直接从命令面板运行时打开导入页。 |

切换聊天后，**Trace** 命令仍可能恢复先前正在复查的会话。要检查新选中的聊天，使用**查看执行 Trace**。复查位置会随窗口恢复；离线文件正文需要重新导入。

## 准备请求与响应的详细记录

已保存的执行历史与详细请求正文是两层数据。关闭详细记录时，已有的 Turn、工具活动和其他持久事件仍可查看；打开 Trace 本身不会开启详细记录，也不能补回过去未保存的请求。

需要复查下一次运行的模型输入和输出时，先进行以下设置：

1. 连接运行该会话的 App Server。在 Workbench 设置中进入 **聊天 > 执行轨迹**。在 Agents 窗口中，从底部账号菜单打开**设置**，搜索并打开**执行轨迹**设置页。
2. 打开**记录详细请求与响应**。
3. 在 **App Server 所在机器上的保存目录**中输入绝对路径。本地连接可以使用**选择目录**；远程连接要填写远程 App Server 主机上的路径。
4. 选择**保存轨迹设置**。
5. 保存工作，并按当前部署方式重启所属 App Server。只重开 Ash 窗口可能继续复用原来的服务器。
6. 返回设置并选择**刷新**。确认**当前后端**显示详细记录已启用，而不只是开关已勾选。
7. 回到会话，运行需要观察的下一轮任务，再打开执行 Trace。

设置页区分“已保存的配置”和“正在运行的后端状态”。保存后提示需要重启时，当前进程仍使用原配置。**刷新**会丢弃这个设置页中尚未保存的修改。

详细记录覆盖 Agent、上下文压缩和工具内辅助模型调用的请求与响应。它记录 ModelService 的语义数据，不提供 HTTP 报文、逐个流式片段或所有内部模型调用。

## 导出并导入一个捕获文件

最直接的文件来源是你刚打开的会话 Trace。也可以使用 Ash 评测或其他捕获过程已经生成的、符合版本 3 rollout 格式的 JSON 文件。普通聊天导出、任意 JSON 和 OTLP span 导出不是这个导入器的输入格式。

### 保存当前记录

1. 在会话 Trace 中选择**刷新**，等待本次加载结束。
2. 打开工具栏的**更多操作**，选择**导出 Trace**。
3. 保存下载的 `session.agent-trace.json`。
4. 如需确认文件可供离线复查，按下一节重新导入，检查目标事件和所需正文。

导出固定的是点击时**全部已加载事件**，包括筛选后看不见的事件。导出过程中，查看器还会尝试读取这些记录引用的已保存正文；无法取得正文时，捕获会标为不完整。点击后才出现的新事件不自动加入这次文件。

同一时间只能进行一次导出。导入或导出的文件大小上限为 64 MiB；后端记录容量更大，不代表整个捕获一定能导出。导出失败时查看页面错误，不要把当前筛选当作缩小导出范围的办法。

### 离线复查

1. 在 Agents 窗口的命令面板执行**打开离线捕获**；在 Workbench 执行**开发人员：打开执行 Trace**。
2. 在工具栏选择**更多操作 > 导入 Trace**。
3. 选择版本 3 rollout JSON 文件。
4. 确认状态显示 **已导入 · 文件名**，然后在执行树中选择事件。

导入成功后，查看器使用文件中的快照，不再跟随原会话的新事件。离线文件缺少的正文也不会从原 App Server 自动补回。连续选择多个文件时，以最后选择的文件为准。

文件需要包含 `formatVersion: 3`、`sessionId`、`threads` 和 `historyPrefixes`。同一 Thread 内的事件序号必须递增。若提示“需要 rollout 格式版本 3”，应重新取得兼容的导出，不能只改版本号。

导入内容在当前编辑器中保留。关闭窗口后，Ash 可以恢复离线入口，但不会自动恢复文件内容，需要再次导入。先保留下载文件。

## 筛选和定位事件

执行树先按 Thread 组织，再显示各轮 Turn 和事件。子 Thread 嵌套在父 Thread 下。每个 Thread 保留自己的事件顺序；不能把所有行当作一条按时钟排序的全局时间线。模型诊断证据在已记录的 Thread 前缀位置显示。

1. 在**筛选执行事件**中输入事件类型、Thread ID、Turn ID、事件 ID 或记录里的文字。例如，用 `modelResponseEvaluated` 查循环决策，用 `modelAttemptFailed` 查模型 attempt 失败。
2. 选择**仅显示错误**，进一步缩小到失败相关事件。
3. 选择一个匹配事件，查看**概览**中的类型、序号、记录时间和错误。需要完整字段时，切换到**原始记录**。
4. 清空筛选并关闭**仅显示错误**，再查看前后的输入、调用和结果。

文字筛选是不区分大小写的普通子串匹配，搜索标识、显示文字和事件记录。它不是正则搜索，也不会全文搜索按需加载的全部请求正文。要搜索正文，先打开**输入**或**输出**里的正文区段，再在只读编辑器内使用查找。

**仅显示错误**包括失败的 Turn、模型调用、工具错误、失败的循环决策、被阻断或失败的 Hook，以及未正常结束的模型 attempt。正常取消不一定被当作错误。要查取消过程，关闭错误筛选，再搜索 `modelAttemptCancelled` 或 `turnInterrupted`。

筛选只改变树里的显示，不会删除记录。已定位事件被隐藏时，详情可以继续保留，页面会提示“当前显示筛选隐藏了该事件”。因此，右侧有详情而左侧没有匹配行，不代表记录错位。

### 键盘操作

* `Tab`：在筛选、执行树和详情页签之间移动。
* 上下方向键、`Home`、`End`：在执行树中导航。
* 左右方向键：折叠或展开树节点。
* `Enter` 或空格：激活详情页签和导航操作。
* `Alt+F1`：打开当前 Trace 区域的无障碍帮助。
* `Alt+F2`：打开 Accessible View，读取筛选后的事件和当前详情，包括执行树视口外的事件。
* `Escape`：关闭帮助或 Accessible View，回到原控件。

查看会话 Trace 时，页面会读取新保存的事件。隐藏或关闭编辑器会停止查看器轮询并释放订阅；再次显示时会补读。关闭查看器不会关闭后端的详细记录设置。

## 阅读输入和输出

先选中事件，再切换到**输入**或**输出**。有正文时，选择**已保存正文**，或按消息角色列出的正文区段，打开只读内容。

| 你选中的记录 | 阅读方式 |
| --- | --- |
| 用户消息、已接受的 Turn | 在**输入**中检查已保存输入。 |
| 工具调用 | 在**输入**中检查工具参数。 |
| 工具结果、Agent 消息 | 在**输出**中检查结果或回复。 |
| 模型 attempt | 在**输入**和**输出**中检查与同一 attempt 关联的详细证据。 |

模型正文会标明数据所处的阶段：

* **Core 语义请求 · 附件转换前**：Core 层交给模型服务的语义输入。
* **模型服务语义请求 · 附件转换后**：附件转换后的语义请求。要专门看这一阶段，可选择 `modelRequestPrepared` 事件。
* **模型服务响应**：该 attempt 已保存的完成响应。
* **结束前收到的部分输出**：失败、取消或其他终止前已收到的内容，不应当作完整答案。

这些记录不等同于网络上的原始请求，也不证明模型内部如何思考。**原始记录**显示的是选中的事件记录；详细正文需要进入相应的**输入**或**输出**区段。

### 判断正文为什么缺失

| 提示 | 含义和下一步 |
| --- | --- |
| 未启用请求证据 | 按前述设置启用并重启 App Server，再观察之后的运行。过去缺失的请求不能补回。 |
| 此事件的当前页签没有已记录正文 | 检查是否选对事件和输入、输出页签。不是每个事件都有正文。 |
| 此 Trace 未包含所选正文 | 当前离线捕获没有内嵌该正文。回到原会话检查是否仍可读取，再重新导出。 |
| 正文因记录上限而省略 | 该正文没有完整保存，不能从查看器还原。 |
| 诊断存储不可用 | 检查设置中的目录和后端错误。已有执行历史仍可读取。 |
| 诊断证据不完整 | 检查省略计数、所需正文和关系警告，避免把缺失证据当作没有发生。 |

如果状态显示有记录**待写入**，稍后刷新并重新检查正文，再导出需要的记录。待写入与已省略是不同状态。

详细记录的上限为每份正文 8 MiB、每次捕获 128 MiB 和 32,000 条诊断事件。存储故障也可能造成缺失。Turn 成功与记录完整性是两回事。

## 沿关系追查工具和子任务

**关系**页签显示所选对象的入向和出向关联。存在目标记录时，选择关系可以跳到对应事件；跳转会清除当前显示筛选。缺少目标的关系不能跳转。

例如，要检查一次工具结果是否进入后续模型输入：

1. 找到工具调用或工具结果，在**输入**或**输出**中确认参数和结果。
2. 选择后续的模型 attempt，打开**输入**，加载 **Core 语义请求**的正文。
3. 切换到**关系**，查找**结果出现在模型输入中**。
4. 选择该关系，核对跳转到的工具结果及其调用标识。

这个关联需要已保存 Core 输入中的调用标识与当前 Thread、Turn 的工具结果对应。仅有相近的时间或前后排列不能证明模型消费了某个结果。没有关系时，先检查正文是否已加载，再检查文件是否包含相应证据。

复查子任务时，可以从父 Thread 的**已收到子任务结果**事件进入**关系**，沿**子任务结果返回**跳到子 Thread 的结果；**等待条件已满足**可以帮助核对已记录的等待请求与返回结果。执行图还可以显示已有证据支持的模型调用、工具、Code Mode 和终端关联。

页面可能显示关系警告。导出时也会排除捕获范围外的事件或因果证据，并在 `graph.warnings` 中保留提示。没有足够证据的关联保持未知。

## 检查 Hook 为什么阻止了操作

配置了 Hook 的任务会保留执行状态。工具没有继续执行时，可以先搜索 `hookRunUpdated`，选择对应事件：

1. 在**概览**中核对 Hook ID、Hook 执行 ID、触发事件、工具名称和耗时。
2. 查看结果是**已继续**、**已阻断**、**失败**还是**已取消**，并阅读已有原因。
3. 如果捕获包含对应的 Hook 执行记录，在**输入**中检查程序、参数、工作目录和进程输入；在**输出**中检查退出码、标准输出、错误输出及截断标记。

Hook 的状态记录与详细进程正文分开保存。正文缺失或被截断时，不要据此推断 Hook 没有运行；先检查详细记录设置和当前捕获的完整性。

## 理解循环决策和失败

搜索 `modelResponseEvaluated`，可以阅读已保存的循环决策。记录会区分**执行工具**、**继续生成**、**完成本轮**、**本轮失败**或**被新输入替代**，并显示停止原因和消息阶段。

消息阶段包括**进度说明**、**阶段性答案**和**最终答案**。一次模型生成显示“本次生成完成”，不必然表示整个 Turn 已完成；结合循环决策和 Turn 最后的状态判断。

例如，**本轮失败**配合**达到输出 token 上限**，说明这次循环因输出截断失败。要继续排查，查看同一 Turn 的输入、部分输出和原始记录，而不是只看聊天窗口是否出现文字。

存在 `modelAttemptAccounted` 记录时，**关系**中的**已提交的模型账目**可以把模型 attempt 连接到对应的用量记录。缺少匹配证据时，对应关系仍未知。重复模型调用本身不能证明发生了重试，也不能据此还原完整的 agent loop 因果链。

## 保护捕获内容

详细记录可能包含用户消息、指令、附件内容和工具结果。记录保存在 App Server 所在机器；远程连接时，这个位置是远程主机。记录功能本身不将捕获上传到外部服务，但导出和分享会产生新的文件副本。

分享前检查导出文件，确认接收人可以看到其中的内容。不要把**仅显示错误**或文字筛选当作脱敏：执行 Trace 导出仍包含被隐藏的事件和可读取的正文。当前查看器不提供基于显示筛选的安全脱敏导出。

关闭编辑器只停止阅读，不删除后端记录和已经下载的文件。需要停止后续详细记录时，在**执行轨迹**设置中关闭开关、保存，并重启所属 App Server，再确认当前后端状态。

## 区分另一个开发者 Trace 查看器

命令面板还提供 **开发者：打开 Trace 查看器**（**Developer: Open trace viewer**，`ash.trace.open`）。这是用于 App Server 性能诊断的 OTLP WebSocket 查看器，与本页的执行 Trace 是两个入口。

它需要在 App Server 启动前配置 `ASH_TRACE_WEBSOCKET_ADDR` 和由 32 个随机字节编码成 64 个十六进制字符的 `ASH_TRACE_WEBSOCKET_TOKEN`，再在查看器中输入地址与令牌连接。仅接受受支持的本机回环 WebSocket 地址，只接收连接之后完成的 span，不回放会话历史。

该查看器按名称、结果和 trace ID 筛选，导出**筛选后的 OTLP**，最多保留 2,000 条 span 和 8 MiB。断开连接保留本次采集，重新连接开始新采集。它的 `ash-traces.json` 不能作为版本 3 rollout 文件导入执行 Trace。

只有在排查 RPC、模型调用或 HTTP 的耗时与 span 关系时，才需要这个开发者入口。检查会话输入、工具结果和子任务时，从对话菜单或命令面板打开**执行 Trace**。开发者接入说明见[源码中的 OpenTelemetry Trace 文档](https://github.com/chogng/ash/blob/bb040bb5cd00070a375e88fdcc7d05fc01ab6d58/crates/otel-trace-websocket/README.md)。
