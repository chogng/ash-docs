# 创建和管理自动化任务

自动化任务让 Agent 在指定时间处理项目工作，例如每天总结进展、定期检查代码或执行一次稍后的任务。你可以在 **Automations** 中保存指令、执行目录和时间规则，再查看每次运行的结果。

## 开始之前

本文依据当前主分支实现，已发布安装包的功能以实际版本为准。使用具备自动化功能的 Ash 构建，并确认执行宿主可以连接、目标目录可访问、模型和账号可用。**Automations** 入口和 **Run on** 中的可选宿主取决于已连接宿主实际提供的能力。

桌面 Agents 窗口可以[连接已保存的 SSH 宿主](/docs/remote/ssh.md#在-agents-窗口连接宿主)。未提供自动化能力的远端组件不会成为可选执行宿主。

自动化到期后会启动 Agent，正常消耗模型用量。它沿用所选执行目录的模型和权限配置，创建计划不会自动批准将来的文件修改、命令或其他工具操作。首次使用时，先安排一个范围明确的只读任务。

## 创建第一个计划

1. 在 Agents 窗口的活动栏选择时钟图标 **Automations**。
2. 选择 **New automation**。也可以选择 **Daily briefing**、**Review changes** 或 **Weekly recap** 模板，再修改打开的表单。选模板不会立即创建任务。
3. 在 **Name** 中填写容易辨认的名称，在 **Instructions** 中说明要检查的范围和期望结果。
4. 先在 **Run on** 中选择执行宿主，再在 **Directory** 中填写该宿主上的项目完整路径。切换宿主会清空之前的目录和对话选择，需要重新填写。
5. 在 **Schedule** 中选择时间规则，并检查下方 **Upcoming runs** 的时间和时区。
6. 确认 **Enabled** 已勾选，选择 **Save automation**。只想先保存草稿时，取消勾选 **Enabled**。
7. 回到任务列表，核对名称、指令、目录、启用状态和下次运行时间。

例如，可以把指令写成：

```prompt
检查这个项目最近一天的 Git 更改，列出可能的错误和缺少的测试，标明文件位置。只给出检查结果，不修改文件，也不提交或推送代码。
```

**Conversation** 默认使用 **New conversation for each run**，每次新建对话。需要延续上下文时，展开该选项并选择指定对话。计划保存明确的对话和目录；之后切换活动窗口、项目或聊天不会自动改变执行目标。

对话列表只显示所选宿主的候选对话。已连接 SSH 宿主的运行已有对应对话时，可以通过 **Open conversation** 打开该宿主中的聊天。宿主断开或对话不可用时，先重新连接原宿主并刷新状态，不要通过再次运行计划来尝试打开对话。

## 选择执行时间

| Schedule 选项 | 使用方式 |
| --- | --- |
| **Every day** | 每天按指定时区和钟点执行。 |
| **Weekdays** | 周一至周五按指定时区和钟点执行，不自动排除节假日。 |
| **Days of the week** | 勾选一个或多个星期，填写钟点和时区。 |
| **Every N minutes** | 按固定分钟间隔执行，范围为 1 至 525600 分钟。 |
| **Once** | 选择未来的日期和时间，按日期输入框标明的本机时区填写。 |

每天和每周的规则使用 `Asia/Shanghai` 这样的时区名称。保存前查看 **Upcoming runs**：它展示后端计算的近期执行时刻和时区，预览本身不会运行任务。时区或时间无效时，先修正表单中的错误。

固定间隔从已保存的起点计算，不从上一次完成时刻重新计时。如果需要每天当地时间 09:00 执行，选择 **Every day**，不要用每 1440 分钟代替。

采用夏令时的地区，某个本地钟点不存在时会跳过该次触发；同一钟点出现两次时，只使用较早的一次。

## 先运行一次，再检查结果

保存后选择 **Run now**，可以立即验证目录、模型、权限和指令。立即运行会新增一条运行记录，不改变原定的下次运行时间。

1. 在 **Run history** 中选择本次运行。
2. 查看状态，以及 **Scheduled time**、**Started**、**Finished**，区分原定时间和实际执行时间。
3. 在 **Result** 中阅读最终回复，在 **Changed files** 中检查本次记录的文件更改。
4. 需要完整对话时，选择 **Open conversation**。只查看详情不会自动离开 Automations。

每次运行保留当时的任务版本、指令和执行目录。编辑计划后，旧运行详情仍显示原来的版本。结果和文件更改只对应这次运行，不把同一对话中其他轮次的工作算进来。

结果暂时没有加载成功时，选择 **Refresh result**。**No final response has been recorded for this run** 表示尚无已记录的最终回复；它不等于运行成功。**No recorded file changes** 也只说明没有记录到文件更改。

## 处理需要输入和失败的运行

**Needs attention** 汇总等待输入的运行，以及各任务最新一次运行中的失败项。常见状态包括：

| 状态 | 下一步 |
| --- | --- |
| **Pending**、**Running** | 等待开始或正在执行，查看详情中的进度和时间。 |
| **Needs input** | 选择 **Continue in Chat** 或 **Open conversation**，检查请求并回应。 |
| **Stopping** | 已请求停止，等待最终状态，不要当成已经停止。 |
| **Completed** | 阅读结果，检查是否达到了你的任务目标。 |
| **Failed** | 阅读错误原因，处理环境、账号、目录或权限问题。 |
| **Stopped** | 运行已停止。检查停止前的结果和文件更改。 |
| **Skipped** | 本次没有执行，查看错过时间或运行重叠等原因。 |

创建自动化不免除权限批准。即使窗口已关闭，需要用户处理的运行仍会等待；重新连接后，打开关联对话处理请求。

处理失败原因后，可以从运行详情选择 **Run current version**。它使用计划当前配置创建新运行，不重放旧版本。已有未结束运行时，先查看它的状态，必要时停止，避免重复执行。

## 编辑、暂停和停止

选择任务名称打开详情，可以检查 **Task version**、执行宿主、目录、时间规则和历史。

* **Edit automation**：修改计划并保存。已创建的运行继续使用原来的版本。编辑已有计划时不能直接更换执行宿主。
* **Pause**：阻止后续定时触发，已经开始的运行继续执行。使用 **Enable** 恢复计划。
* **Stop run**：中断某一次未结束运行。等待状态变为 **Stopped** 或其他最终状态后，再判断结果。
* **Duplicate**：打开一份默认暂停的可编辑副本。检查指令、目录和时间后保存，需要运行时再启用。
* **Delete**：删除不再需要的计划。有未结束运行时不能删除，先处理或停止该运行。删除计划不会自动撤销它已经完成的文件修改或工具操作。

如果想暂时停用并保留配置，使用 **Pause**。不要用关闭 Automations 页面或窗口来暂停计划。

## 关闭窗口、休眠与离线

已启动的本机后台宿主负责计划调度。关闭某个窗口或所有窗口不会取消启用中的计划，但电脑必须保持可运行，宿主也必须仍在运行。

| 情况 | 实际行为 |
| --- | --- |
| 电脑关机或休眠 | 期间不能执行任务。 |
| 一次性任务错过时间 | 宿主恢复后补执行一次，保留原定时间和实际开始时间。 |
| 重复任务错过多次 | 跳过错过的时刻，继续计算下一次，不集中补跑全部历史任务。 |
| 上一次运行尚未结束 | 定时触发默认跳过；立即运行也不会另开并发运行。等待输入的运行也属于未结束。 |
| 宿主断开连接 | 页面可能保留旧结果，不能把它当成最新状态。重新连接原宿主并刷新。 |

当前不提供系统登录后的自动启动，也不保证后台宿主意外退出后自动拉起。重启电脑或显式停止后台服务后，需要重新启动宿主，再打开 Automations 检查下次时间与历史。不要把本机计划当作关机后仍可执行的云端服务。

断开 SSH 宿主连接不会自动暂停计划或停止运行。远端计划能否继续执行取决于远端后台服务、网络、模型和权限是否可用；连接成功不代表无人值守执行已得到保证。需要暂停时，先在原宿主的计划上选择 **Pause**；重新连接后再检查运行历史。

## 查找任务和接收通知

使用 **Search automations** 按名称、指令、目录或宿主名称查找。来自多个宿主的计划显示各自的执行宿主，操作前先核对宿主和目录。**All**、**Enabled** 和 **Paused** 筛选计划状态；选择 **Clear filters** 恢复全部计划。

窗口打开时，失败或需要输入的新状态会显示通知。成功通知默认关闭，可以勾选 **Notify when an automation completes**，对应设置为 `sessions.automations.notifyOnSuccess`。通知中的 **View result** 直接打开运行详情。首次加载已有历史不会逐条补发通知。

历史加载失败时，页面会保留上次取得的记录并提示错误。选择页面的 **Refresh** 重试读取，不要通过再次新建或运行任务来刷新历史。

## 常见问题

**没有 Automations 入口。** 确认正在使用具备该功能的 Agents 窗口，并已连接支持自动化的宿主。入口由宿主能力决定，较早构建或远端组件不保证提供该功能。

**保存时提示任务已更改。** 其他窗口可能已更新同一计划。刷新并重新打开任务，核对最新内容后再编辑，避免覆盖已有更改。

**下次运行时间不符合预期。** 检查计划是否启用、规则使用的是固定间隔还是当地钟点，以及时区、星期和近期执行预览。一项已执行的一次性任务没有新的定时执行时间。

**点击停止后仍显示运行中。** 停止是发给实际执行中的 Agent 的请求。等待最终状态，必要时重新连接并刷新；停止不会撤销此前已完成的操作。
