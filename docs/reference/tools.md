# 工具

工具让 Ash Agent 读取信息、修改工作区、运行验证和访问外部系统。本页帮助你辨认工具用途，并通过执行记录检查 Agent 的结论。实际可用工具取决于当前产品、会话和已启用的能力。

## 工具类别

| 类别 | 用途 | 检查什么 |
| --- | --- | --- |
| 文件读取与搜索 | 查找文件、读取内容、定位文本 | 路径、搜索范围和实际返回的证据 |
| 文件编辑 | 创建或修改文件 | 改动内容和受影响的文件 |
| 命令执行 | 运行构建、测试和开发命令 | 参数、工作目录、输出与退出状态 |
| 浏览器交互 | 读取页面、操作控件或验证网页行为 | 页面地址、操作目标和实际结果 |
| MCP 外部工具 | 调用已连接服务 | 服务器来源、输入参数和外部影响 |
| Advisor 咨询 | 根据已有上下文获得第二意见 | 顾问模型、咨询问题、建议与用量 |
| Skill 读取 | 按需加载工作方法或参考资料 | 来源、所选内容以及它与任务的关系 |

浏览器和外部服务能力需要对应宿主或连接可用。目录中看不到某个工具时，模型不能仅凭提示词获得该能力。

## 一次工具调用包含什么

主模型提出工具名称和参数后，Ash 检查具体动作与权限。获准后执行工具，记录结果，再把结果交给主模型。

| 记录 | 表示什么 |
| --- | --- |
| 工具请求 | 主模型计划调用什么，以及使用哪些参数 |
| 批准请求 | 操作正在等待决定，还不能认定已经执行 |
| 执行结果 | 工具实际返回了什么，是否成功、失败或取消 |
| Agent 回复 | 主模型如何解释结果，以及准备采取什么下一步 |

工具名称本身不决定权限。对文件、网络或外部系统的影响取决于具体参数，完整说明见[权限与批准](/docs/configure/permissions.md)。

## 检查工具活动

在当前会话中查看调用参数和结果，重点核对：

* 文件路径是否属于要处理的项目。
* 搜索结果是否覆盖关键文件，是否需要继续读取。
* 命令是否真正执行完成，测试是否成功。
* 外部操作影响了哪个账号和资源。
* 最终结论是否由这些结果支持。

命令输出中出现测试名称，不等于测试已经通过；只看到启动信息，也不等于操作已完成。结果未知时，先检查实际状态。

## 查看顾问结果

桌面工作台将 `advisor` 调用与结果合并到 **Advisor** 卡片中。展开可查看建议和结果提供的模型、问题、对话序列与用量；聚焦标题后按 `Enter` 展开或收起。Ash Code 在工具结果中显示建议。

顾问没有自己的工具，不能自行读取新文件或执行建议。主模型发起咨询后可以继续验证并执行任务；手动 `/advisor ask` 显示结果后等待你的要求。命令与限制见 [Advisor 文档](/docs/agents/advisor.md)。

## 工具不可用或失败时

| 情况 | 检查方式 |
| --- | --- |
| 工具未出现在当前目录中 | 检查所需产品能力、扩展和服务连接 |
| 等待批准 | 查看批准请求，不要重复提交同一操作 |
| 返回参数或文件错误 | 核对路径、参数和当前工作区 |
| MCP 连接失败 | 查看服务器配置、身份验证和连接错误 |
| 操作中断或结果未知 | 确认是否已产生改动，再决定继续方式 |

## 扩展工作方法和工具

[Skills](/docs/customize/skills.md) 提供说明、脚本和参考资料，通过 `$name` 选择；[MCP 服务器](/docs/customize/mcp-servers.md) 提供外部工具。Skill 启用或 MCP 配置保存，都不会自动授权其后续操作。
