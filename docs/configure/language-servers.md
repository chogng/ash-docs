# 配置语言服务器

语言服务器提供代码补全、定义和引用跳转、诊断等语言能力。本指南帮助你检查服务器状态、使用内置 Rust 支持，或配置已经安装的语言服务器。

本文对应当前源码中的设置入口和 Rust 集成，不代表已有正式安装包发布。实际能力还取决于所用版本、执行环境和服务器支持。语法着色可以独立工作，看到代码颜色不代表语言服务器已启动。

## 打开语言服务器设置

1. 打开项目并确认后端连接正常。
2. 从命令面板执行 **配置语言服务器**（**Configure Language Servers**），也可以在图形设置的 **编辑器 > 语言服务器** 中进入，或搜索 `lsp`。
3. 在 **工作区目录** 中选择要检查的目录，再从 **语言服务器** 列表选择目标。

命令 ID 是 `ash.languageServers.open`，聊天中的 `/lsp` 也打开同一页面。**语言 ID** 输入框用于在 Extensions 中查找相应语言的服务器，搜索本身不安装服务器。

此设置页的启用状态、程序路径和高级配置属于所连接 App Server 的 profile。选择工作区目录只改变检查范围，不创建目录级服务器配置。不要把本页的完整高级配置片段粘贴到 `settings.json` 后期待同样效果；Rust 的语言选项另见下文。

## 查看状态、停止和重启

选择状态栏左侧的 **语言服务**（**Language Services**），或从命令面板运行同名命令，打开按工作区文件夹分组的服务器菜单。命令 ID 是 `ash.languageServers.manage`，与修改配置的入口不同。

1. 核对工作区文件夹，再选择服务器名称。相同服务器可以在不同文件夹下分别运行。
2. 选择 **查看日志**（**View Logs**），在 **输出** 中阅读完整消息。
3. 临时停用当前窗口中的实例时，选择 **停止服务器**（**Stop Server**）。需要重新运行时，选择 **重启服务器**（**Restart Server**），再检查状态和日志。

停止会取消该实例的在途请求并清除其诊断；后台语言请求不会自动重新启动已手动停止的实例。停止和重启不修改已保存的启用状态或程序路径，也不保存编辑器文件。要持久停用服务器，请在设置页修改 **启用服务器**。

每个文件夹下还提供批量停止和重启操作；多根工作区另有 **停止所有服务器** 和 **重启所有服务器**。批量操作仅控制当前窗口中已经启动过的实例，重启也包括其中已停止的实例，不会把列表中所有未启动的候选一并启动。单独选择服务器的 **重启服务器** 也可显式启动尚未启动的候选；按需下载的服务器此时可能开始下载。

使用键盘时，上下方向键选择服务器，向右键打开操作，向左键返回，`Escape` 关闭菜单并恢复焦点。菜单加载失败时，再次打开 **语言服务** 重试。

## 使用 Rust 语言支持

当前源码包含默认启用的 Rust 扩展。打开 Rust 项目并产生语言请求时，Ash 检查可用的本地 `rust-analyzer`；没有可用实例时，按需下载固定版本并校验完整性。

1. 在项目所在的执行环境中准备 Rust 工具链，确认 `cargo` 和 `rustc` 可用。
2. 打开包含 `Cargo.toml` 的项目和 Rust 源文件。
3. 使用代码补全或[定义跳转](/docs/editing/editing-and-navigation.md#查看定义和引用)，并观察状态栏中的服务器状态。
4. 首次准备失败时，打开对应日志，检查网络、平台和运行环境。

托管下载清单覆盖 macOS、Linux GNU 和 Windows MSVC 的 x64 与 arm64。其他平台需要自行准备兼容的服务器。下载 `rust-analyzer` 不会安装或修复 `cargo`、`rustc` 或项目依赖。

仅查看服务器列表不会下载或启动进程。停用 Rust 扩展或 `rust-analyzer` 服务器会阻止探测和安装。其他服务器的默认启用规则不同，不能按 Rust 的行为推断。

### 按工作区调整 Rust 选项

Rust 集成会读取当前目录生效的 `rust-analyzer` 设置树，包括用户、工作区和文件夹设置，传给该目录的语言服务器。使用普通[设置](/docs/configure/settings.md)调整 Rust 语言选项时，先确认设置范围；多根工作区中的不同文件夹可以有不同的有效值。

相关设置变化后，受影响的服务器会使用新配置重新启动；删除覆盖后重新采用剩余范围的有效值。Rust 初始化选项也会使用这些值，不只在服务器已经启动后发送。这里不改变服务器的启停、程序路径和安装来源，也不表示其他语言服务器自动支持同样的设置映射。

## 更改服务器配置

1. 选择服务器，按需要调整 **启用服务器**。
2. 要使用自己的安装，在 **可执行程序路径（可选）** 中填写后端主机上确实存在、可以执行的绝对路径。不要填写目录或包含参数的整条命令。
3. 选择 **保存服务器配置**，等待重新读取完成，再检查是否有错误。

已有集成的路径留空时，使用该集成的默认来源，例如语言包或环境中的程序。Rust 设置显式路径后，该路径优先；路径无效时不会自动改用其他来源。

配置、语言包或启用状态发生变化后，受影响服务器的旧会话结束，后续请求按新配置启动；未改变的服务器继续工作。停用、卸载或撤销权限也会取消该服务器的在途请求，不再采用旧实例的迟到结果。**刷新** 只重新读取状态并重填表单，不是重启按钮，也不会替你保存草稿。重复保存相同值不保证重启。

**使用默认配置** 删除该服务器的整项用户覆盖，包括高级配置。它恢复各服务器自己的默认行为，不保证服务器一定启用。出现保存冲突时，先刷新并检查现有值，再决定如何修改。

## 添加自行安装的服务器

使用自定义服务器前，先确认程序支持 stdio LSP，并能在目标执行环境启动。这一入口不会安装任意程序，也不接受 TCP 地址或服务器网址。

1. 输入新的 **服务器 ID**。使用 1 到 64 个小写英文字母、数字或连字符，首尾不能是连字符。
2. 勾选 **启用服务器**，填写可执行程序的绝对路径。
3. 在 **高级配置（JSON）** 中填写非空的 `languageIds`，再按服务器要求补充参数和选项。
4. 确认没有其他启用的服务器使用相同语言 ID，再保存。替换已有语言服务器时，先停用旧服务器。

例如，已经安装的 Python 服务器需要声明它处理的语言：

```json
{
  "languageIds": ["python"],
  "args": []
}
```

这只是高级字段示例，不包含可执行路径，也不保证空参数适合所用程序。具体语言 ID、启动参数和配置键应按该服务器说明填写。

高级配置只接受以下字段，使用严格 JSON，不能包含注释：

| 字段 | 用途 |
| --- | --- |
| `languageIds` | 服务器负责的语言 ID 字符串数组 |
| `args` | 追加的启动参数数组，每个参数一个字符串，不经过 Shell 展开 |
| `environment` | 启动环境变量，键和值均为字符串；Rust 可用性探测也使用这些覆盖值 |
| `initializationOptions` | 传给服务器的初始化选项 |
| `settings` | 供服务器请求工作区配置时读取的对象 |

不要把用于查找扩展的 **语言 ID** 输入框当作这里的 `languageIds`。同一配置中多个服务器处理同一语言会产生冲突。

## 排查没有补全或诊断

* **显示可用但没有结果**：列表中的可用项表示当前配置提供该语言的服务器候选，不表示服务器已安装、进程正在运行或初始化已成功。打开对应语言文件，检查是否启用，并发起一次语言请求。
* **启动失败或反复崩溃**：从 **语言服务** 选择对应服务器的 **查看日志**。需要处理的失败通知也提供日志与重启或重试操作。警告和完整错误保留在 **输出** 中，不会全部弹出通知。
* **状态栏显示索引或下载进度**：进度项显示服务器名称和当前操作，服务器提供百分比时会一并显示。选择进度项打开对应输出通道。扫描结束后仍可能继续索引或检查，不能把一项完成视为全部完成。只有实际需要网络下载时才显示 **正在下载**，本地探测和已校验缓存复用不显示下载进度。
* **修改 PATH 后仍找不到程序**：刷新不会重新取得后端启动时的 PATH。可以填写实际绝对路径，或在保存其他工作后重新启动所属后端。
* **自定义路径无效**：修正该服务器的路径，或停用它；要清除整项覆盖，选择 **使用默认配置**。单个服务器的路径或安装失败不会阻止读取配置，也不会使无关语言的服务器一同失效。
* **通过 Rust 环境变量选择工具链**：在高级配置的 `environment` 中设置所需的 `RUSTUP_TOOLCHAIN` 等变量。可用性探测和实际启动使用相同覆盖值，用户配置优先于集成默认值；所选工具链仍需要在后端环境中可用。

语言服务器仍受目录权限和运行环境限制。放宽权限不能修复错误路径、缺失工具链或重复语言路由。没有诊断也不表示项目已经通过测试。
