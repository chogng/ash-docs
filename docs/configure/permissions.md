# 权限与批准

Ash 在执行工具前检查具体动作、目标范围和当前策略。允许的动作可以执行；需要你决定的动作会显示批准请求；被策略禁止的动作会停止。本页帮助你理解每次批准的含义。

## 检查动作和目标

| 能力 | 常见动作 | 检查重点 |
| --- | --- | --- |
| 读取文件 | 搜索代码、读取内容 | 哪些文件或目录会被读取 |
| 写入文件 | 创建、编辑、移动或删除 | 精确路径和改动范围 |
| 启动进程 | 执行命令、构建或测试 | 程序、参数、工作目录和环境 |
| 网络访问 | 下载或连接远端服务 | 主机、端口和发送的数据 |
| 使用凭据 | 使用账号、密钥或 token | 使用哪个账号、访问什么服务 |
| 外部修改 | 修改问题、仓库或云资源 | 目标资源和具体操作 |
| 系统配置 | 安装环境或更改系统设置 | 设置范围和恢复方式 |
| 用户界面 | 控制页面或应用 | 操作哪个页面、应用和控件 |

同一个工具因参数不同，可能得到不同决定。读取项目文件和读取项目外的凭据文件，需要分别判断。

## 回答批准请求

1. 查看操作内容、参数和目标，确认它们符合你的任务要求。
2. 需要执行时，选择一次性批准；范围不合适时，选择拒绝。
3. 查看工具执行结果，再决定是否继续下一步。

一次性批准只允许当前请求对应的工具调用执行一次。更换路径、参数或其他影响授权的条件后，原批准不能自动复用。拒绝会结束这次请求，Agent 可以根据结果调整方案。

保存长期权限规则是独立的配置操作。一次批准不会自动变成对同类命令的永久允许。

## 选择 Ash Code 的权限模式

Ash Code 在页脚左侧显示权限模式，使用 `Shift+Tab` 循环选择。模式在一轮任务提交时固定，中途切换影响后续轮次。

| 页脚显示 | 遇到原本需要你批准的动作时 |
| --- | --- |
| **ask permissions on** | 由你选择一次性批准或拒绝 |
| **auto review on** | 使用已配置的审查模型评估，再按策略决定；审查不可用或失败时仍询问你 |
| **bypass permissions on** | 跳过这次批准交互，保留策略检查和执行记录 |

跳过交互不能覆盖禁止规则或沙箱必须满足的限制。需要你逐次检查动作时，选择 **ask permissions on**。

自动权限审查与 [Advisor 顾问](/docs/agents/advisor.md) 用途不同。前者帮助判断某个动作的风险，后者为开发任务提供第二意见；顾问的建议不授予执行权限。

## 理解沙箱和目录权限

沙箱限制程序能够访问的文件和网络。动作获准后，仍必须在要求的限制下运行。所需限制无法实施时，Ash 会拒绝启动。

目录授权也不等于允许该目录内的所有行为。工作区配置、Skills 或 MCP 声明可以请求功能，但不能自行授予凭据、执行权限或更宽的目录访问。

浏览器、MCP 和顾问调用可能把任务内容发送到外部服务。批准时同时关注操作本身和外发数据。

## 处理失败与不确定结果

| 情况 | 下一步 |
| --- | --- |
| 你拒绝了操作 | 说明希望缩小的范围或允许的替代动作 |
| 策略禁止操作 | 查看禁止原因，调整任务范围 |
| 命令返回非零退出码 | 检查命令输出；普通程序错误不表示需要更高权限 |
| 沙箱无法实施所需限制 | 检查平台支持和具体错误，不把它当作自动放宽权限的理由 |
| 崩溃或断线后结果未知 | 先检查文件或外部状态，再决定是否重新执行 |

停止任务不会撤销已经完成的写入。对于结果未知的请求，Ash 不会自动重发已经开始的操作。
