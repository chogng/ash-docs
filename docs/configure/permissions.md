# 权限与批准

Ash 分别检查目录访问、具体工具动作和执行限制。打开项目时授予目录权限，并不等于批准后续所有命令；批准一次操作，也不会自动扩大以后可以访问的目录。本页说明在哪里调整这些选择，以及批准后应该检查什么。

## 先区分三种控制

| 控制 | 决定什么 | 用户入口 |
| --- | --- | --- |
| 目录授权 | 对后端上的哪个目录，允许读取、写入、运行命令或加载项目内容等能力 | 桌面打开文件夹提示；会话设置中的 **执行与权限** |
| 动作批准 | 当前工具要对哪个目标做什么，是否需要你确认 | 会话 **权限** 菜单、Ash Code `/permission` 和批准请求 |
| 执行限制 | 本地进程的文件与网络访问范围，平台是否能实施要求的隔离 | **执行与权限**中的默认值；具体命令检查及沙箱诊断 |

目录授权是可访问范围的上限；一个会话可以选择更小的范围，每次工具调用仍会检查具体路径。策略禁止的动作不会因为选择“跳过权限审批”就自动获准。

## 选择当前对话的权限模式

### 图形界面

在会话输入区域打开 **权限**（**Permissions**），选择下列模式。菜单打开时，可以用方向键和 `Enter` 选择，也可以按 `1`、`2`、`3` 分别选择自动、手动、跳过权限审批。`Esc` 关闭菜单。

| 模式 | 何时使用 | 对需要批准的动作如何处理 |
| --- | --- | --- |
| **自动**（**Auto**） | 希望先自动审核，不能确定时再询问 | 使用审核模型评估动作；不能判断时请求你确认 |
| **手动**（**Manual**） | 希望自己核对需要授权的动作 | 显示批准请求，由你批准一次或拒绝 |
| **跳过权限审批**（**Bypass permissions**） | 已理解任务风险，并接受减少交互 | 跳过大部分审批，访问范围限制仍然生效 |

图形界面选择 **跳过权限审批**时会再次提示风险：命令可能修改或删除文件，并执行外部操作而不逐次询问。确认前检查项目和任务范围。

选择用于下一轮提交。已经开始的任务保留提交时的权限模式，不会因为你在输入区域切换模式而立即改用新设置。**Plan**、**Ask** 仍然是调查分析模式，权限选择不会把它们变成允许修改的任务模式。

### Ash Code 终端界面

输入 `/permission` 打开同一组权限选项，也可以直接输入：

```text
/permission manual
/permission auto
/permission bypassPermissions
```

查看页脚显示的 **Manual**、**Auto** 或 **Bypass permissions**，确认当前模式。任务运行期间，页脚显示正在执行这一轮的模式；下一轮选择不会改变已运行的操作。

`Shift+Tab` 在当前 Ash Code 中切换 Agent、Plan 等任务模式，不是切换权限模式的默认快捷键。

## 回答一次性批准

出现请求时，先阅读操作说明，再核对参数和目标：

| 操作 | 重点检查 |
| --- | --- |
| 读取或搜索文件 | 目录、文件集合，是否涉及项目外内容 |
| 创建、修改、移动或删除文件 | 精确路径、覆盖范围，是否可恢复 |
| 执行命令 | 程序、参数、工作目录，命令可能产生的修改 |
| 联网或使用凭据 | 服务、目标主机、使用的账号及发送的数据 |
| 修改外部资源 | 仓库、问题、云资源等准确目标，以及具体操作 |
| 系统或界面操作 | 影响的设置、应用、页面和控件 |

1. 内容符合任务要求时，选择 **批准一次**（**Approve once**）。
2. 范围过大或目标不对时，选择 **拒绝**（**Decline**），再说明可接受的范围。
3. 继续查看工具输出；批准表示允许尝试执行，不代表动作已经成功。

图形界面可用 `Tab` 到达按钮，再按 `Enter` 或空格。一次性批准绑定当前请求与工具调用；路径、参数、环境、来源、所需能力或策略发生相关变化后，不能沿用旧批准。拒绝结束当前请求，Agent 可以根据拒绝结果提出不同方案。

一次批准不会自动保存为永久允许。当前批准界面没有“本次会话始终允许”“此项目始终允许”或“保存为长期规则”的选项；长期执行规则属于独立配置。

例如，允许在项目目录内运行测试，不等于允许随后删除项目、向其他主机上传内容，或读取项目外的凭据。

## 设置默认审批和命令访问

在会话窗口打开设置，选择 **执行与权限**（**Execution and permissions**）。它控制普通对话和工作流的执行默认值，不等同于输入区域针对当前对话的选择。

1. 设置 **默认审批模式**。
2. 设置 **命令文件访问**：选择 **只读**或**可写入已授权目录**。
3. 设置 **命令联网**：选择 **禁止**或**允许**。
4. 点击 **保存执行默认值**，核对页面显示的已保存默认值。

新对话和未明确指定审批模式的工作流继承此默认值；对话选择和工作流自己的审批设置优先。命令默认策略在后端重新加载配置后用于新准备的命令，正在运行的命令不会被终止。

这些是命令默认值，不是完整授权：审批或已配置的执行规则可能允许更宽的命令访问，目录授权和受管网络规则仍然有效。允许联网也不自动允许使用任何账号或修改外部服务。

设为默认跳过审批时，页面会要求确认。若出现“后端设置已变化”或保存冲突，先记下需要保留的输入，再点击 **刷新**；刷新会丢弃未保存草稿，然后才能重新修改和保存。

## 打开文件夹时授予目录权限

桌面打开尚无已保存授权的目录时，会询问“是否信任此文件夹中的文件？”。检查完整路径后选择：

| 选择 | 授予的主要能力 |
| --- | --- |
| **以只读模式打开**（**Open Read Only**） | 读取、浏览、搜索、观察文件变化和查看仓库 |
| **信任文件夹并启用开发功能**（**Trust Folder & Enable Features**） | 在读取之外允许写入、运行命令、更改仓库，并加载项目指令、配置和相关开发功能 |
| **取消**（**Cancel**） | 不完成这次目录打开 |

“信任文件夹”在这里是目录能力选择。已有授权时可能不再询问；多根工作区仍逐个目录检查。状态栏的 **只读文件夹**或**受限工作区**反映当前有效目录能力，不能当作所有 Agent 动作都获准的标志。

仅有文件读取权限，不等于允许执行项目脚本或加载项目配置。详细打开步骤见[打开和管理项目](/docs/editing/workspaces.md)。

## 查看、更改或撤销目录授权

在已连接可信桌面宿主的会话设置中，打开 **执行与权限**：

1. 从 **已保存的目录授权**选择已有目录，或在 **App Server 所在机器上的目录路径**填写绝对路径。
2. 核对页面显示的已保存能力。
3. 在 **目录文件与命令权限**中选择 **只读**、**读写**或**读写并运行命令**。
4. 点击 **保存目录权限**；不再需要该授权时，选择对应目录后点击 **撤销目录授权**。

路径属于后端所在机器，不一定是正在显示窗口的机器。**自定义已保存权限**表示当前能力集合与上述预设不同，应先检查具体能力，再决定是否改成预设。

这里的预设只更改文件、仓库和命令相关能力，保留已有的指令、配置、Skill、MCP、Hook、Plugin 等其他发现权限。因此，把一个开发目录改成“只读”，不会顺带移除此前保存的所有项目内容加载权限。需要去掉整个已保存授权时，使用 **撤销目录授权**。

撤销生效后会阻止后续操作，但不会撤回已完成的写入。Agent 交互式 Shell 会话依赖的目录授权被撤销或收紧时，相关命令会取消，后续输入也会被拒绝；这不会自动结束整个 Agent 任务或无关命令。检查实际进程和文件状态后，再决定下一步操作。

Web 连接可以查看和修改执行默认值，但不能在此授予后端目录权限；目录编辑需要已连接的可信桌面宿主。

## 自动审核、模型和项目资料

在图形界面 **权限 → 审核模型…**（**Review model…**）中，可以选择独立的审核连接、模型和思考强度。审核模型用于判断动作风险，不会改变主任务模型。

若需要让审核了解项目背景，在权限菜单选择 **准备审核环境…**，或在该图形会话输入 `/guardian setup`：

1. 先为会话选好项目，选择 **扫描项目…**。
2. 检查扫描范围。近期会话、终端历史命令名和其他仓库信息是可选来源；如选择用当前任务模型整理，过滤后的资料会发送给该模型。
3. 扫描生成草稿后，逐项阅读、编辑、接受或排除。
4. 点击 **保存已接受的条目**。扫描中可按 `Esc` 取消。

近期会话扫描默认上限为 50 个会话、每会话 200 条命令、所有日期；启用前可以调整。它聚合命令名和目标，不读取对话消息或保留普通参数。检查覆盖量，避免把有限扫描当作完整历史。

保存项目资料、确认目标属于你，或在 `ASH.md` 中写入说明，都不构成操作授权。项目来源变化后会重新检查；需要重新确认的目标说明不能沿用旧确认。

自动审核与 [Advisor 顾问](/docs/agents/advisor.md)用途不同。前者检查某个动作，后者为任务提供第二意见；顾问的建议不授予执行权限。

## 理解沙箱和网络限制

本地进程在动作允许的文件和网络范围内运行。要求的隔离在当前平台无法实施时，Ash 会拒绝启动，而不是自动改为无限制执行。

编辑器设置中的 **沙箱**（**Sandbox**）可以查看后端候选、当前目录的只读准备检查，以及允许查看时的目录授权。**准备通过**只是当前检查结果，每个命令和终端启动前仍会重新检查。

使用受管网络时，命令运行过程中仍可能针对实际目标出现单独的网络批准。批准继续该网络请求，文件限制仍然有效；拒绝会关闭该请求，不会把整条命令从头重跑。

MCP 服务器和远端服务有自己的执行环境。本地命令沙箱不能隔离远端副作用；当前 stdio MCP 的启动也没有接入命令沙箱。启用本地 MCP 前应先确认程序可信，见[MCP 服务器](/docs/customize/mcp-servers.md)。

## 浏览器控制与文件上传

浏览器能力有独立开关：`workbench.browser.enableChatTools` 控制 Agent 浏览器工具，`workbench.browser.enableCDP` 控制高级 CDP，后者默认关闭。开启能力后，具体动作仍需通过任务审批与访问检查。

高级 CDP 只能访问当前任务的隔离 Agent 页面和上下文，不能操作 Ash 工作台或普通用户页面。网络请求继续遵循任务的网络策略；本地进程沙箱不能代替浏览器权限检查。

通过浏览器工具上传文件时，还需要当前任务对文件的读取权限。Ash 在读取上传内容时检查目录授权和敏感路径限制，并拒绝多硬链接文件。当前这条上传通道不支持来自 SSH 或提供商执行目标的文件；单次最多 16 个文件，总内容不超过 4 MiB。不要把该限制套用到 ChatGPT 页面的附件上传。

出现 **BrowserFileAccessDenied** 时，先核对本机绝对路径、目录授权、文件大小和文件来源。不要通过改名、链接或切换跳过审批来绕过拒绝。高级控制不可用时，检查桌面宿主与后端是否使用兼容版本，以及两个浏览器开关是否启用。

关闭普通浏览器工具会取消相关操作并关闭 Agent 页面；关闭高级 CDP 会释放 CDP 连接和临时上下文。停止浏览器操作不会撤销已经提交到网站的内容。

## 排查拒绝、失败和未知结果

| 情况 | 下一步 |
| --- | --- |
| 目录只读，无法编辑或运行终端 | 检查该目录的实际授权，需要时在桌面修改；切换审批模式不补齐目录能力 |
| 项目指令或扩展未发现 | 检查对应内容加载或发现权限，普通读取权限不覆盖这些能力 |
| 你拒绝了操作 | 说明希望缩小的范围或允许的替代动作 |
| 策略禁止操作 | 查看禁止原因，调整目标或任务，不反复切换跳过审批 |
| 自动审核不可用或无法判断 | 查看具体错误和后续批准请求，核对审核模型及连接；不可用不等于默认允许 |
| 命令返回非零退出码 | 检查输出、参数和依赖；普通程序错误不表示需要更高权限 |
| 沙箱无法实施要求 | 查看平台和具体错误；不要把它当成自动放宽限制的理由 |
| 保存设置失败或版本冲突 | 保留必要输入，刷新后再保存；不要假定失败的设置已经生效 |
| 崩溃或断线后结果未知 | 先检查文件或外部状态，再决定是否重新执行 |

停止任务不会撤销已完成的操作。对结果未知的执行，Ash 不会自动重发已经开始的请求；在确认状态前，也不要要求再次提交同一写操作。
