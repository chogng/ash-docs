# 调整设置

使用 Ash 设置改变编辑器和界面的工作方式。先选择用户、工作区或文件夹范围，再通过图形界面或对应的 JSON 文件修改普通设置。语言服务器等专用管理页面有各自的配置范围。

本文依据 2026 年 10 月 19 日的主分支源码；公开安装包的功能以实际发布版本为准。

## 打开设置

打开 **Ash 设置**（英文界面为 **Ash Settings**）。默认快捷键为 Windows/Linux 的 `Ctrl+,`，macOS 的 `⌘+,`。也可以从左侧管理菜单进入设置，或在命令面板中搜索命令名称。

如果快捷键被更改，使用[键盘快捷方式](/docs/configure/keyboard-shortcuts.md)查找当前绑定。

### 选择默认设置编辑器

搜索 `workbench.settings.editor`，在 **默认设置编辑器** 中选择 `ui` 或 `json`。默认值为 `ui`，使用图形设置；设为 `json` 后，普通设置入口会打开用户设置 JSON。此偏好也适用于 Agents 窗口的设置入口。

只想临时切换时，使用图形设置搜索栏旁的 **打开设置（JSON）**，或用户设置 JSON 编辑器标题栏的 **打开设置（图形界面）**。切换不修改默认偏好，也不会保存或丢弃尚未保存的 JSON 修改。图形控件不预览未保存的 JSON 草稿。

## 选择设置范围

使用搜索框旁的 **设置目标** 按钮选择配置保存的位置：

| 目标 | 配置保存的位置与用途 |
| --- | --- |
| **用户** | 当前 profile 的用户设置，作为不同项目的个人偏好 |
| **工作区** | 单文件夹项目的 `.vscode/settings.json`，或多文件夹工作区文件中的 `settings` 对象 |
| 文件夹名称 | 多文件夹工作区中，该根目录的 `.vscode/settings.json`，只影响适用的文件夹设置 |

未打开项目时只显示 **用户**。单文件夹项目使用 **工作区**，没有额外的文件夹层。不同范围显示可用于该范围的设置，不是每个用户设置都能改为项目设置；远程用户目标尚不支持。

### 只修改一种代码语言

在搜索框输入语言 ID，例如：

```text
@lang:plaintext @id:editor.fontSize
```

随后修改字号控件，会在当前目标中保存纯文本语言的字号覆盖，不改动基础字号。语言筛选只显示已注册语言中支持语言覆盖的设置；未知语言不会返回结果。移除 `@lang:` 后回到基础设置，已有语言覆盖仍保留。

可以组合 `@lang:plaintext @modified` 查找该目标中保存的纯文本语言覆盖。重置同样只移除所选目标、所选语言的覆盖。

## 找到并修改一个选项

1. 在设置搜索框中输入关键词、说明文字或设置 ID，例如 `editor.fontSize`。
2. 修改对应控件的值。
3. 检查页面是否显示保存错误，并在编辑器里观察实际效果。

搜索会过滤当前页面的设置；`@lang:` 还会选择后续编辑所用的语言。输入搜索本身不会修改配置。某些设置连接账号或服务，需要额外的管理操作；不要把所有设置行都理解成普通 JSON 值。

## 找回自己改过的设置

在搜索框输入：

```text
@modified
```

也可以在设置筛选中选择 **已修改**。这会列出当前目标中存在覆盖值的设置；选择了 `@lang:` 时，只检查该语言的覆盖。还可以结合普通关键词继续缩小范围。

“已修改”表示所选范围中保存过值，并不一定表示它与默认值不同。即使显式保存了默认值，或保存的是 `false`、`0`、空字符串，它仍可能出现在结果中。

不带 `@lang:` 的 `@modified` 不会把仅存在于语言覆盖块中的设置列为基础设置的修改。普通配置项旁的 **已配置** 标记同样按所选目标和语言判断。需要移除这层覆盖时，使用该项菜单中的重置操作，而不只是手动填回你记得的默认值。保存失败时先处理错误，原配置可能仍然有效。

## 在 JSON 中编辑

选择图形设置搜索栏旁的 **打开设置（JSON）**，会打开当前目标的配置文件。命令面板中的 **首选项: 打开用户设置（JSON）** 则直接打开用户设置。

搜索框恰好是一个设置 ID，或 `@id:设置ID` 时，通过搜索栏按钮切换到 JSON 会定位已有的对应值；如果该项尚未写入 JSON，不会为此创建覆盖。用户设置 JSON 可通过编辑器标题栏的 **打开设置（图形界面）** 返回；也可以从命令面板打开图形设置，再检查目标。

要直接编辑某一项，打开普通设置项的菜单，选择 **在 JSON 中编辑**（**Edit in settings.json**）。基础设置已有值时会选中它的值；尚未写入时按默认值插入未保存的草稿，修改后仍需保存才会生效。工作区文件中的设置在 `settings` 对象内定位或插入。

在 `@lang:` 筛选下，这个操作定位已有的语言覆盖块；缺失时不会插入基础设置，也不会自动创建该语言块。可以先在图形界面保存语言值，再打开 JSON 检查。账号或其他使用专用服务管理的设置可能没有这个操作。

如果逐项编辑提示 JSON 有错误，先通过搜索栏的 **打开设置（JSON）** 打开文件并修复语法，再重新定位该设置。已有注释和未保存内容会保留。

例如，调整编辑器字号的配置片段是：

```json
"editor.fontSize": 18
```

把它放在现有设置对象中，并检查相邻属性之间的逗号。不要用这一行替换整个文件。用户设置使用 JSONC，可以保留注释。

在文本编辑器中保存后，配置才会写入。新插入的设置项也可能只是未保存的修改。无效 JSONC 或不符合设置要求的值会被拒绝，不能把文件里的草稿当成已生效配置。

## 复制一项配置

普通配置项的菜单提供 **复制设置为 JSON**。它复制 `"设置键": 值` 片段，不带最外层花括号，可用于现有设置对象。

复制本身不会保存或更改配置。复制值来自当前目标与语言；没有对应覆盖时，复制的是当前窗口的默认值。账号或其他具有专用管理界面的设置可能不提供这个菜单。

## 管理文件路径规则

在图形设置中搜索下列设置 ID，可以直接添加、编辑或移除路径规则：

| 设置 | 用途 |
| --- | --- |
| `files.exclude` | 在 Explorer 中隐藏匹配的文件和文件夹 |
| `search.exclude` | 在项目搜索中排除匹配的文件和文件夹 |
| `explorer.autoRevealExclude` | 打开匹配文件时，不在 Explorer 中自动定位并选中它；文件仍可在树中显示 |
| `files.readonlyInclude` | 将匹配的文件设为只读 |
| `files.readonlyExclude` | 为只读规则添加可编辑的例外；不会绕过文件系统权限 |
| `workbench.localHistory.exclude` | 不为匹配的文件保存本地历史记录 |

1. 选择 **添加规则**，输入路径规则，例如 `**/generated/**`。
2. 选择 **保存**，或在输入框中按 `Enter`。
3. 修改已有规则时，选择该行的 **编辑**；放弃当前编辑时选择 **取消**，或按 `Esc`。
4. 不再需要某条规则时，选择该行的 **移除规则**。

路径规则支持 `*` 和 `**`。在规则行上按 `Enter` 可编辑，按 `Delete` 可移除，上下方向键可切换规则。路径不能为空，也不能与另一条启用中的规则重复。保存报错时，先处理提示并检查原规则，不要把输入框里的内容当成已生效配置。

`files.exclude`、`search.exclude` 和 `explorer.autoRevealExclude` 还提供 **同目录文件匹配条件（可选）**。例如，路径填 `**/*.js`，条件填 `$(basename).ts`，表示同目录存在同名 `.ts` 文件时才应用这条规则。只读和本地历史规则没有这个条件字段。

### 显示默认隐藏的文件

`files.exclude` 默认隐藏任意层级的 `.git`、`.svn`、`.hg`、`.jj`、`.DS_Store` 和 `Thumbs.db`。想显示其中一类文件，在规则列表移除对应默认规则，例如 `**/.git`。

移除默认规则会在当前目标保存一个值为 `false` 的覆盖，列表只显示仍启用的规则。也可以在相应目标的设置 JSON 的 `files.exclude` 对象中加入或修改相应条目：

```json
"files.exclude": {
  "**/.git": false
}
```

保留该对象中你仍需要的其他规则。删除这个 `false` 条目会重新启用默认隐藏规则。对整个 `files.exclude` 使用 **重置设置** 会移除当前目标的全部覆盖；其他层的规则仍可能生效，不会删除文件。

## 修改显示语言

在 **常规 → 显示语言** 中选择语言。列表包含内置语言和已安装的语言包；也可在设置中搜索 `language`、`locale` 或“语言”。如果界面提示需要重启，保存工作后按提示操作。

## 设置截图快捷键

在设置中搜索 `screenshot.globalShortcut`，或打开 **截图** 分类。**全局截图** 默认关闭；开启后，桌面应用可在 Ash 处于后台时响应截图快捷键。

按键组合在 **键盘快捷方式** 中修改，命令名称是 **聊天：添加截图**。截图设置页只提供全局开关；屏幕权限指引在发起截图时出现。截图无障碍帮助位于 **辅助功能** 分类。具体操作参见[截图与标注](/docs/editing/screenshots.md)。

## 配置听写

打开 **语音输入** 分类，选择听写服务并管理本地模型。以下设置分工不同：

| 设置 | 用途 |
| --- | --- |
| `dictation.enabled` | 启用消息、编辑器和终端中的听写，默认 `true` |
| `dictation.showButton` | 显示消息输入框的麦克风按钮，默认 `true`；设为 `false` 后仍可使用听写命令 |
| `dictation.backend` | 选择本地、云端 API 或 Codex 订阅，默认 `local` |
| `dictation.model` | 选择本地模型包 ID；建议在模型列表中选择已安装的模型 |

`dictation.model` 填的是模型包 ID，不是任意文件路径。更改它不会自动安装模型；先在模型列表中完成安装或导入，再选择 **使用模型**。

旧键 `dictation.localModel` 会在读取设置时迁移到 `dictation.model`。新旧值相同会清理旧键；值冲突或旧值无效时，Ash 保留原文并报告问题。此时打开用户设置 JSON，将需要的有效模型 ID 保留在 `dictation.model` 中，移除旧键，再保存。不要把旧配置示例中的键继续加回去。

### 在 Chat 中使用听写命令

先聚焦当前可见的 Chat 或 Cowork 输入框，再运行 **听写消息**（**Dictate message**）。它把识别文字写入输入框，不会自动发送。停止后检查文字，再自行发送；隐藏或切换对话会取消本次录音。

需要按住录音时，在[键盘快捷方式](/docs/configure/keyboard-shortcuts.md)中为 **听写：按住录音**（**Dictation: Hold to record**）设置快捷键。录音开始后，按住至少半秒再松开可完成转写；短按会丢弃录音。模型或麦克风仍在准备时松开也会取消，不会稍后自动录音。仅从命令面板执行这个按住命令不会开始录音。

桌面的 **启动语音模式**（**Start Voice Mode**）是另一条入口：它在最近聚焦且仍可见的 Chat 中开启实时语音对话，而不是只把文字放进草稿。先确认目标对话与语音配置；听写模型设置不等于实时对话模型设置。

## 选择默认面板位置

在编辑器窗口的设置中搜索 `workbench.panel.defaultLocation`，选择工具面板默认位于 `left`、`right`、`top` 或 `bottom`，默认是底部。它用于新工作区，已有工作区保留保存的位置。

要立即移动当前面板，使用[面板位置命令](/docs/getstarted/user-interface.md#显示或放大底部工具)。Agents 窗口使用自己的面板位置记录，不随编辑器窗口的这个默认设置改变。

## 调整长行和差异视图

在设置中搜索 `editor.wordWrap`，选择长行的显示方式：

| 值 | 显示方式 |
| --- | --- |
| `off` | 不自动换行，是默认值 |
| `on` | 在编辑器可见宽度处换行 |
| `wordWrapColumn` | 在 `editor.wordWrapColumn` 指定的列处换行 |
| `bounded` | 在可见宽度和指定列两者中较窄的位置换行 |

`editor.wordWrapColumn` 默认为 `80`，接受正整数。显示换行不会向文件插入换行符。

差异视图使用 `diffEditor.wordWrap`，默认 `inherit`，继承上述模式和对应语言的配置，包括 `wordWrapColumn` 与 `bounded`。设为 `on` 或 `off` 可以单独控制比较视图的换行。相关设置保存后会更新已经打开的比较。

需要在比较视图中显示语言服务提供的操作或引用信息时，开启 `diffEditor.codeLens`，默认关闭。它只控制显示，仍需要当前语言提供 CodeLens。如何在比较中编辑工作文件，见[编辑文件与导航代码](/docs/editing/editing-and-navigation.md#在差异视图中修改工作文件)。

## 调整代码高亮

`editor.semanticHighlighting.enabled` 可设为 `true`、`false` 或默认值 `"configuredByTheme"`，用于选择是否显示语义高亮。默认跟随主题。

要按 token 类型设置颜色或字体样式，编辑 `editor.semanticTokenColorCustomizations`。例如，把下面的片段合并到用户设置对象中，可为注释指定颜色和斜体：

```json
"editor.semanticTokenColorCustomizations": {
  "rules": {
    "comment": {
      "foreground": "#6a9955",
      "italic": true
    }
  }
}
```

`editor.tokenColorCustomizations` 仍支持 `comments`、`strings` 等预设类别。当前 Ash 不支持其中的 `textMateRules`，也不支持主题中的 TextMate scope、`tokenColors` 或 `.tmTheme` 文件。迁移旧主题时，应改用语义 token 规则，不能只复制原来的 TextMate 配置。

## 设置内置浏览器工具

在设置中搜索 `workbench.browser.enableChatTools` 可控制 Agent 的内置浏览器工具。`workbench.browser.enableCDP` 是独立的高级选项，默认关闭。开启前先了解[浏览器工具](/docs/reference/tools.md)和[权限与批准](/docs/configure/permissions.md)。浏览网页、填写表单和管理已保存密码，见[内置浏览器与网站密码](/docs/editing/browser.md)。

## 配置代码语言支持

在 **编辑器 > 语言服务器** 中，或运行 **配置语言服务器**（**Configure Language Servers**），可以检查语言服务器、启用或停用服务器，以及填写自行安装的可执行程序路径。Rust 的按需准备、日志和高级 JSON 用法见[配置语言服务器](/docs/configure/language-servers.md)。

这份配置保存到所连接 App Server 的 profile，与普通用户设置 JSON 分开。选择 **工作区目录** 只改变服务器检查范围，不创建该文件夹专用的覆盖。

## 刷新账户的托管设置

组织提供的托管设置可能限制部分选项。打开 **Codex 审查** 设置页，查看托管设置状态；它会显示对应账户、最近尝试和已有的成功刷新时间。选择 **刷新托管设置** 可重新获取，刷新期间按钮不可用。

这项操作使用主 GitHub 账户，与同一页用于访问仓库的所选账户无关。不要用“仓库可以访问”判断托管设置已经刷新成功。

* 提示重新连接时，先重新连接 GitHub，再刷新托管设置。
* 提示限流时，等待后重试。权限或客户端兼容性错误需要联系管理员。
* 网络或无效响应造成失败时，按提示检查连接后重试。若页面显示 **已保留之前接受的设置**，先前接受的策略仍可能影响当前选项；失败不表示限制已经解除。

## 保存默认日志记录级别

需要在之后的窗口中继续使用某个记录级别时，在 **输出** 面板选择支持记录级别控制的通道，先设置级别，再在同一菜单中选择 **设为默认**。这项偏好属于当前界面 profile 的启动配置，不是普通用户设置 JSON 中的设置键。

扩展通道的默认值只用于该扩展；没有扩展归属的通道保存通用默认值。没有保存值或启动覆盖时，默认级别是 `info`。当前仍沿用旧默认值的日志来源会跟随更新，显式指定级别或已经单独调整为其他级别的来源不会统一改变。如何区分记录级别与显示筛选，见[用输出日志定位问题](/docs/support/troubleshooting.md#用输出日志定位问题)。

## 当前配置范围

图形控件通常显示所选层的覆盖或默认值，不是当前文件所有配置层合并后的结果。普通配置按默认值、用户、工作区、文件夹的顺序组合，再应用语言覆盖；管理策略也可能限制最终值。用户设置已保存但某个项目仍有不同表现时，检查项目和语言配置。图形页的 `@modified` 只反映当前目标与语言，不是所有配置层的汇总。

桌面更新设置 `update.policy` 会优先显示系统策略规定的渠道，其次才是用户值。受策略控制时，修改用户设置不能覆盖它；需要变更时联系维护该策略的管理员。

通过命令参数在不同编辑器组打开设置时，各组保留独立的搜索和目标。页内切换 JSON 使用来源组，不会改写另一组的搜索。Agents 窗口的工作区、文件夹及语言查询会转到共享设置编辑器。

桌面应用的用户配置按当前 profile 保存；浏览器开发界面的用户配置保存在该浏览器的数据存储中。使用不同 profile 或清除浏览器站点数据后，不应预期设置自动相同。

## 排查问题

| 现象 | 可以检查什么 |
| --- | --- |
| 搜不到设置 | 检查当前目标，清除 `@modified`、`@lang:` 等过滤条件，再用设置 ID 搜索 |
| 填回默认值后仍显示已修改 | 使用重置，移除所选目标与语言的覆盖 |
| JSON 修改没有效果 | 是否已经保存、语法和值是否合法，是否使用同一 profile、目标与语言 |
| 保存提示冲突 | 先查看外部修改，保留需要的内容，再按冲突提示处理 |
| 找不到工作区或文件夹目标 | 先打开项目；单文件夹项目只显示工作区，多文件夹工作区才列出各根目录 |
