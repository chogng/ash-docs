# 使用集成终端

Ash 的集成终端让你在工作台中运行 Shell 命令，例如查看项目状态、启动开发服务或运行测试。本指南介绍如何选择 Shell、运行和补全命令、拆分和移动终端，以及查找输出、关闭进程和恢复会话。

本文依据当前源码介绍桌面工作台中的终端。已发布安装包的功能以实际版本为准。执行命令前，先确认当前目录和命令会修改的内容。

## 打开终端并运行命令

1. 在 Ash 中打开项目文件夹。
2. 打开命令面板，运行 **聚焦终端**。也可以从顶部的 **终端** 菜单选择该操作。
3. 首次打开时，Ash 会使用默认 Shell 创建终端。等待提示符出现，再输入命令并按 `Enter`。

先运行一个只读命令检查所在目录。Bash、Zsh 等 Shell 中可以使用 `pwd`，PowerShell 中可以使用 `Get-Location`，命令提示符中可以使用 `cd`。

在包含多个文件夹的工作区中，新终端优先使用当前编辑文件所属的根目录；无法确定时会显示文件夹选择器。按名称和完整路径选择目标，取消不会自动改用第一个根。`terminal.integrated.cwd` 等目录配置也按所选根解析，启动后仍应检查实际目录。

重排根目录或增删其他根，不会把保留根中的运行终端切换到另一目录。需要在另一个项目新建终端时，先打开该项目的文件，或在选择器中选择它。详见[多根工作区](/docs/editing/workspaces.md#使用多根工作区)。

运行测试或开发服务时，使用项目说明中提供的命令。终端不会自动为项目安装语言运行时或依赖。

要保存经常使用的构建、检查或测试命令，并配置任务分屏和打开文件夹时自动运行，参见[运行和配置任务](/docs/terminal/tasks.md)。

## 运行编辑器中的选中文本

代码编辑器中的 Shell 命令可以直接发送到活动终端，无需复制粘贴。

1. 检查活动终端的 Shell、当前目录和前台程序。确认它正在等待你要发送的输入。
2. 回到代码编辑器，选中要运行的文本。可以选择多行；没有选区时使用光标所在行。
3. 打开命令面板，运行 **终端：在活动终端中运行选中文本**（**Terminal: Run Selected Text in Active Terminal**）。
4. 查看终端输出。操作会提交输入并显示终端，同时保留代码编辑器焦点。

有选区时保留其中的空格和多行内容；没有选区时去掉当前行首尾的空白，空白行不执行。文本发送到活动终端，不会因编辑文件属于另一个项目而切换已有终端的目录。若前台正在运行其他程序，它会接收这些输入。

没有终端，或活动终端已退出、只读时，Ash 会尝试新建可输入的终端，必要时让你选择工作区文件夹。正在重连的终端不会接收本次输入；准备期间关闭或切换目标终端也会取消发送。连接恢复并核对输出后，再决定是否重试。

## 运行当前文件或插入路径

要运行编辑器中当前打开的磁盘文件，先保存需要执行的修改，再运行 **终端：在活动终端中运行当前文件**（**Terminal: Run Active File in Active Terminal**）。Ash 把文件路径发送到活动终端执行，并保留代码编辑器焦点。没有可输入的终端时，会尝试新建终端。

这个命令运行磁盘上的文件，不会自动保存未保存的编辑，也不会替你选择语言解释器。先确认文件可按当前 Shell 的方式执行，核对终端目录和前台程序。文件必须属于同一执行宿主；本机文件不能直接交给 SSH 终端，虚拟或未保存的资源也不能使用此入口。

当前路径发送支持执行端已识别的 Bash、Zsh 和 PowerShell。未知 Shell 和 Windows 上的 Bash 路径转换不受支持；这不表示所有平台都已完成实机验证。

只想把路径放进输入行时，把文件、文件夹或编辑器标签拖到终端内容区。它插入第一个资源的引用路径，不自动按 `Enter`。检查输入后再决定是否执行。浏览器文件若没有可用于执行宿主的路径，会提示不可用，不会自动上传文件。

## 返回最近使用的目录

1. 选择正在运行的普通 Shell，确认它可以接收命令。
2. 运行 **终端：转到最近目录…** （**Terminal: Go to Recent Directory...** ）。
3. 用方向键选择目录，按 `Enter` 在该终端执行目录切换。按 `Escape` 取消。

目录来自当前工作区与执行宿主的 Shell 目录记录，不会混入另一宿主的路径。切换终端、重连或改变工作区目录会取消尚未确认的选择。没有记录时，先在终端访问目标目录，并确认 Shell 集成提供目录信息。

`terminal.integrated.shellIntegration.history` 默认保留 100 条历史，分别用于每个终端配置的命令和每个工作区执行宿主的目录。设为 `0` 会禁用两类历史。运行 **Terminal: Clear Previous Session History** 会同时清除保存的命令和目录记录，不删除项目文件。

## 补全终端输入

Shell 集成正常工作时，Ash 默认会在键入命令或参数后，在光标附近显示可用建议，焦点仍留在终端。用上、下方向键选择，按 `Enter` 只插入建议，不执行命令；检查完整输入后，再按 `Enter` 执行。按 `Escape` 关闭建议，`Tab` 仍使用 Shell 自身的补全。

也可以主动打开建议列表：

1. 在支持 Shell 集成的普通终端中输入命令开头，保持输入为单行，并把光标移到末尾。
2. 按 `Ctrl+Space`，或运行 **终端：触发建议**（**Terminal: Trigger Suggest**）。macOS 同样使用 `Control+Space`。
3. 用方向键选择建议，按 `Enter` 插入或替换对应输入，不执行命令。按 `Escape` 取消。
4. 回到终端，检查完整命令、目录、参数和路径的引号，再按 `Enter` 执行。

在设置中搜索以下设置 ID：

* `terminal.integrated.suggest.enabled`：默认开启。关闭后，自动建议和 **触发建议** 入口都停用，不影响 Shell 自身的补全。
* `terminal.integrated.suggest.quickSuggestions`：分别控制键入命令、参数和未知输入时的自动建议。默认 `commands`、`arguments` 为 `on`，`unknown` 为 `off`；设为 `false` 可关闭这类自动建议，保留主动触发入口。
* `terminal.integrated.suggest.suggestOnTriggerCharacters`：控制扩展指定字符触发的自动建议，默认关闭。它与快速建议分开控制；只关闭快速建议时，这个选项仍可能触发建议。

内置建议使用同一终端配置中已保存的可信命令历史，按当前输入前缀匹配并补入剩余文本。Bash 和 Zsh 使用 POSIX 路径时，还可补全同一执行宿主、同一授权工作区根内的文件和目录。内置路径建议只处理普通文本，不解析带引号、转义或 `~` 等展开的输入，也不支持 Windows 路径。

已安装、启用并获准提供终端补全的扩展，也可以添加建议。扩展建议可替换提示符中的一段文本；光标不在末尾时，可以主动触发扩展补全。开启触发字符建议后，扩展也可在键入指定字符时提供建议。具体内容取决于扩展；接受后仍要检查整条命令，尤其是包含空格或特殊字符的路径。

多行输入或 Shell 正显示灰色建议文本时，这个入口不可用。自动建议及内置历史、路径建议要求光标位于末尾。自动建议等待 Shell 确认键入内容，不会由粘贴、输入法组合提交或终端程序应答触发。

输入、目录、终端或连接变化会取消原来的选择。扩展撤回提供者后，它的旧建议不能再接受；重新注册或切回原终端不会恢复旧请求。历史数量由[终端历史设置](#返回最近使用的目录)控制，设为 `0` 不会同时关闭路径建议或扩展建议。

### 通过听写输入

先按[听写设置](/docs/configure/settings.md#配置听写)准备语音服务，并在出现提示时完成麦克风许可。

1. 选择正在运行、可输入的终端，确认 Shell 正在等待命令。
2. 选择终端面板标题栏的麦克风，或运行 **终端：开始听写**（**Terminal: Start dictation**）。
3. 说完后选择 **停止听写**，或运行 **终端：停止听写**（**Terminal: Stop dictation**）。
4. 检查插入的文本，再自行按 `Enter` 执行。

听写不会自动执行命令。它会处理部分英文口述符号，例如把 `pipe` 转为 `|`，因此执行前要检查命令、标点和路径。识别结果可能分段插入。选择 **取消听写**、按 `Escape`、切换终端或隐藏面板会取消后续听写，已插入的文本仍需自行检查或删除。

### 减少远程输入的等待感

远程终端回显较慢时，可以在设置中搜索 `terminal.integrated.localEchoEnabled`，从默认的 `off` 改为 `auto`。它会在远程回显延迟达到阈值时，先显示预测的输入；`on` 则不等待远程延迟条件。`terminal.integrated.localEchoLatencyThreshold` 默认是 `30` 毫秒。

输入预测只适用于 Shell 集成已识别的提示符，并且目前只预测末尾输入的可打印 ASCII 字符。当前提示符先收到并显示真实的可打印字符回显后，才会预测后续输入，避免在 Shell 关闭回显时提前显示输入内容。它不会生成命令，也不能证明执行端已收到预测内容。运行命令、输出不匹配或切换到全屏程序时会撤回预测。

`terminal.integrated.localEchoExcludePrograms` 可排除程序，默认包含 `vim`、`vi`、`nano` 和 `tmux`；`terminal.integrated.localEchoStyle` 控制预测文本样式。显示不符合预期时，先将 `localEchoEnabled` 改回 `off`。

## 新建终端和选择 Shell

选择终端标题栏的加号 **新建终端**，使用默认 Shell 创建另一个实例。

要选择不同的 Shell：

1. 打开加号旁的 **选择终端配置** 下拉菜单。
2. 选择列表中的配置，例如 Bash、Zsh、PowerShell 或命令提示符。列表也可以包含已配置的 Shell 和扩展提供的终端配置，具体选项取决于当前执行环境。
3. 等待新终端启动，再检查提示符和当前目录。

带 **默认** 标记的项是当前默认配置。选择配置会创建新终端，不会切换已有终端中的 Shell，也不会把它保存为新的默认配置。

也可以运行 **终端：使用配置新建终端**（**Terminal: Create New Terminal With Profile**），通过快速选择器选择配置。取消选择不会创建终端。

选择期间切换工作区或执行连接会取消这次选择。在新环境中重新打开选择器，核对可用的 Shell。

扩展撤回自定义终端配置的创建入口，不会仅因此关闭已经创建的实例；用该入口新建或重新启动自定义终端仍需要原提供者有效。这不代表扩展被停用、撤权或连接中断后，终端也能继续使用。

要更改以后新建终端使用的 Shell，在同一下拉菜单中选择 **选择默认配置**，或运行命令 **终端：选择默认配置**（**Terminal: Select Default Profile**）。选择结果保存到当前执行平台对应的用户设置，已有终端不受影响。

同一菜单中的 **配置终端设置** 会打开设置界面，并筛选终端设置。**运行任务...** 和 **配置任务...** 分别打开任务选择器和配置流程，详见[运行和配置任务](/docs/terminal/tasks.md)。

如果刚安装的 Shell 没有出现在列表中，先确认它能在对应环境中启动，再重启 Ash 后检查列表。不要直接套用其他编辑器的终端配置文件格式。

### 检查扩展对环境的修改

1. 选择要检查的终端，运行 **终端：显示环境贡献**（**Terminal: Show Environment Contributions**）。
2. 在只读详情中查看启动时记录的扩展修改，以及详情列出的新进程配置。例如，扩展可能向 `PATH` 添加目录。
3. 需要应用修改时，先结束或保存运行中的任务，再从该终端的菜单选择 **重新启动终端**（**Relaunch Terminal**）。若出现关闭提示，核对后再继续。

详情记录扩展选择的修改，不会实时读取 Shell 中的环境变量；启动快照不可用时会明确提示，不能把另一栏的配置当作这个进程已采用的值。扩展配置刚变化时，详情也可能尚未刷新。重新启动会按当前启动设置和扩展配置创建新进程；重新连接或重新加载窗口不会改写原进程的环境，也不会让新配置自动进入旧 Shell。

## 管理多个终端

一个终端适合保留正在运行的开发服务，另一个终端可以运行测试或检查 Git 状态。

* 只有一个终端组时，标题栏通常显示当前终端名称。选择名称可打开该终端的操作菜单。
* 面板中有多个实例时，右侧显示终端列表。选择名称切换到对应实例和终端组。
* 拆分组的成员相邻显示，并以连接线表示关系。每一行的拆分和关闭操作针对该行的终端。
* 把列表中的终端拖到另一终端之前或之后，可以调整组内顺序或加入目标组。横向窗格可拖到左半边或右半边，纵向窗格可拖到上半边或下半边。
* 拖动终端内容与右侧列表之间的分隔线，可以调整列表宽度。列表较窄时使用图标呈现。

切换实例会保留各自的屏幕内容和进程。隐藏终端面板也会保留实例，正在运行的命令不会因为面板隐藏而停止。

使用 **将面板移到左侧**、**将面板移到右侧**、**将面板移到顶部** 或 **将面板移到底部** 调整面板位置时，终端保留进程、输出、待提交输入和分屏比例。顶部和底部面板中的窗格横向排列，左侧和右侧面板中的窗格纵向排列。

标题栏的当前终端名称和拆分、终止按钮是否显示，还取决于 `terminal.integrated.tabs.showActiveTerminal` 和 `terminal.integrated.tabs.showActions`。找不到按钮时，可以使用实例菜单或命令面板。

使用键盘调整面板中的终端时，先选择要移动的终端，再运行 **终端：合并或调整终端顺序...** （**Terminal: Join or Reorder Terminals...** ）。选择目标终端及之前或之后的位置，按 `Enter` 确认。按 `Escape` 取消；移动保留原进程和输出，不会重新运行命令。

### 按名称查找并切换

运行 **终端：切换活动终端**（**Terminal: Switch Active Terminal**），或在快速打开中输入 `term `（含末尾空格），查看当前窗口已打开的终端。输入名称筛选，用方向键选择后按 `Enter`，可聚焦该终端原来的面板或编辑器；按 `Escape` 取消。

选择已有终端不会新建 Shell 或移动它。列表中的行内按钮可以重命名或关闭对应终端；关闭仍遵循[终端关闭保护](#为运行中的命令开启关闭保护)，可能结束运行中的进程。

### 拆分终端

在面板中选择一个正在运行的普通 Shell，选择加号旁下拉菜单里的 **拆分终端**，在同一组内创建另一个 Shell。顶部或底部面板中并排显示，左侧或右侧面板中上下显示。需要使用不同 Shell 时，选择 **使用配置拆分终端**（**Split Terminal with Profile**），再选择配置。

普通拆分沿用原终端的启动配置，包括 Shell 参数和环境变量。之后修改配置列表不会改写原终端的这份配置。需要使用更新后的配置时，从 **使用配置拆分终端** 中重新选择。

新窗格沿用原终端所属的工作区根，优先使用原终端的当前目录；无法取得当前目录时，回退到原终端的启动目录。先检查目录，再运行项目命令。拖动窗格之间的分隔线可调整大小；右侧终端列表的分隔线只调整列表宽度。

用键盘聚焦窗格分隔线后，横向窗格用左右方向键调整，纵向窗格用上下方向键调整。调整大小时默认短暂显示终端的列数和行数；可以在设置中关闭 `terminal.integrated.resizeDimensionsOverlay.enabled`。

运行 **终端：取消拆分终端**（**Terminal: Unsplit Terminal**）可把当前实例移回独立的组，保留其进程和输出。只读、已退出、正在重连的终端，以及扩展自定义终端，不提供普通 Shell 的拆分操作。

### 移到编辑区

选择目标终端后，运行 **终端：将终端移入编辑区**（**Terminal: Move Terminal into Editor Area**）。原实例会作为编辑器标签显示，进程和输出继续保留。要放回面板，运行 **终端：将终端移入面板**（**Terminal: Move Terminal into Panel**）。

编辑区中的普通 Shell 也支持 **拆分终端** 和 **使用配置拆分终端**。新终端在相邻编辑器组中打开，原终端的进程和输出保留。同一终端有多个编辑器视图时，关闭其中一个仍保留进程；关闭最后一个标签才会结束实例。批量关闭需要确认时，取消会保留这次关闭涉及的终端。只想移动位置时，使用移回面板命令。

### 新建终端窗口

在加号旁的菜单中选择 **新建终端窗口**（**New Terminal Window**），或运行同名命令。Ash 会在独立窗口中创建新的终端编辑器，并把焦点移入该窗口。原终端继续保留。

多根工作区仍按新建终端的规则确定目录，必要时显示文件夹选择器。取消选择或创建失败时，Ash 会清理本次创建的窗口和终端。窗口打开后，先确认 Shell 和目录，再输入命令。

### 把运行中的终端移到新窗口

桌面应用中，先聚焦要移动的普通 Shell，再运行 **终端：将终端移入新窗口**（**Terminal: Move Terminal into New Window**）。原终端会移到同一工作区和执行宿主的新桌面窗口中，保留运行中的进程、工作目录、输出和待提交输入。移动完成后，原窗口不再显示该实例。

这个操作需要正在运行、可输入且支持进程重连的终端。只读输出、已退出或正在重连的实例，以及扩展自定义终端，不能这样移动。转移失败时，Ash 会尝试在原窗口恢复；若提示恢复失败，先检查进程和输出，再决定是否重新启动。浏览器入口不提供这条桌面进程转移命令。

## 调整终端字号

在命令面板运行 **终端：增大字号**（**Terminal: Increase Font Size**）、**终端：减小字号**（**Terminal: Decrease Font Size**）或 **终端：重置字号**（**Terminal: Reset Font Size**）。这些命令修改共享的 `terminal.integrated.fontSize`，影响所有终端；重置恢复当前平台的默认字号。也可以在设置中直接修改，支持范围为 `6` 到 `100`。

需要使用滚轮时，开启 `terminal.integrated.mouseWheelZoom`，再按住 `Ctrl` 滚动鼠标滚轮；macOS 使用 `Command`，也支持捏合手势。这个开关默认关闭，关闭时滚轮保持通常的滚动行为。

## 查看命令状态

Shell 集成提供命令信息时，提示符或命令行旁会显示状态标记。把指针停在标记上，可查看等待输入、运行中、成功、失败或取消状态；失败时可显示退出代码。读屏软件也可以读取状态说明。

`terminal.integrated.shellIntegration.decorationsEnabled` 控制显示位置：默认 `both` 同时显示左侧边栏和右侧概览标尺；`gutter` 只显示边栏，`overviewRuler` 只显示概览标尺，`never` 隐藏命令装饰。改变显示位置不会清空命令输出。

这些标记依赖当前 Shell 或执行端提供的信息。提示命令已完成但退出代码不可用时，不能据此判断成功；没有标记也不表示命令没有执行。需要确认结果时，检查命令输出和实际文件状态。

标记关联到可识别的命令时，选择标记可以打开操作菜单。使用键盘时，聚焦标记并按 `Enter`、空格或 `Shift+F10`：

* **复制命令**：复制命令文本。
* **复制输出** 或 **复制命令及输出**：复制这条命令仍保留的完整输出，以及需要时的命令文本。
* **选择命令**：在终端中选中命令输入范围。
* **重新运行命令**：把已结束的命令再次发送到该终端。先检查当前目录和前台程序；需要确认时，核对命令再选择 **运行**。

输出已被清空或截断时，复制输出的操作可能不可用，不能从当前屏幕补出完整历史。重新运行会再次执行命令，不会撤销上一次操作；只想保存证据时，使用复制。

把指针停在已完成命令或其输出上，默认会显示覆盖这段内容的参考线，帮助辨认输出属于哪条命令。它同样依赖 Shell 集成和仍保留的输出；可在设置中关闭 `terminal.integrated.shellIntegration.showCommandGuide`。

### 检查 Git 快速修复

最近一条命令失败后，Ash 可以从仍保留的英文 Git 输出中识别子命令拼写建议，以及 `git push` 缺少上游分支的建议。

1. 等待 Shell 返回空提示符，保留失败命令的输出。
2. 按 Windows、Linux 的 `Ctrl+.`，macOS 的 `Command+.`，或运行 **显示终端快速修复**（**Show Terminal Quick Fixes**）。
3. 选择标为 **插入命令** 的内置 Git 建议并按 `Enter`，只把命令插入提示符。检查命令、远程仓库和分支，再决定是否在终端按 `Enter` 执行。

按 `Escape` 取消。已有输入、输出被清空或截断、没有匹配的 Git 提示时，可能没有可用修复；退出恢复后回放的旧命令不提供修复。它不会覆盖当前输入，也不保证为每种 Git 错误提供修复。切换终端、重连或运行新命令会取消原来的选择。

已安装、启用并获准提供终端快速修复的扩展，也可以针对命令和输出添加动作。扩展动作可能插入或直接执行命令、打开链接，或运行扩展提供的操作。选择前检查动作及其来源，不要把内置 Git 建议“只插入”的行为套用到所有项目。

扩展撤回快速修复提供者后，它的旧动作不能再执行；即使重新注册同一提供者，也需要重新获取建议。

### 接收终端程序通知

支持 OSC 99 通知的终端程序可以向 Ash 通知中心发送消息。`terminal.integrated.enableNotifications` 默认开启；不需要时，在设置中关闭它，或使用通知中的 **禁用终端通知**。

这不会自动为每条长时间运行的命令生成完成提醒，程序本身需要发送通知。通知文字和按钮来自终端程序，选择按钮前先确认其含义。当前不支持该协议的声音、图标或应用筛选；关闭来源终端或禁用设置会撤回相应终端通知。

### 在输出顶部保留命令

粘性滚动会在命令滚出视口后，把对应命令标题保留在终端顶部，方便确认长输出属于哪条命令。它默认开启，需要 Shell 集成提供命令信息。

选择标题可回到原命令位置。使用键盘时，按 `Tab` 聚焦标题，再按 `Enter` 或空格跳转；按 `Escape` 返回终端输入。运行 **终端：切换粘性滚动**（**Terminal: Toggle Sticky Scroll**）可开启或关闭标题。

在设置中搜索 `terminal.integrated.stickyScroll.maxLineCount` 可调整保留的行数，默认为 `5`，范围为 `1` 到 `10`，并且不超过终端可见行数的 40%。`terminal.integrated.stickyScroll.ignoredCommands` 控制不显示标题的命令。清屏、输出被截断或进入全屏终端程序后，原标题可能不再显示；这项功能不额外保存输出。

## 调整选中复制和右键行为

在设置中打开 `terminal.integrated.copyOnSelection`，可在终端持有焦点时自动复制选中的文本。默认关闭；终端查找产生的匹配选区不会因此覆盖剪贴板。

`terminal.integrated.rightClickBehavior` 控制终端内容区的右键操作：

* `default`：Linux 默认值，显示上下文菜单。
* `copyPaste`：Windows 默认值，有选区时复制并清除选区，没有选区时粘贴。
* `paste`：粘贴剪贴板文本。
* `selectWord`：macOS 默认值，选中指针下的单词并显示上下文菜单。
* `nothing`：把右键交给终端，不显示上下文菜单。

按住 `Shift` 再单击右键可打开上下文菜单。使用粘贴类选项前，检查剪贴板和当前前台程序；右键粘贴仍遵循下面的多行粘贴设置。

## 检查多行粘贴

粘贴到终端的换行可能触发命令执行。在设置中搜索 `terminal.integrated.enableMultiLinePasteWarning`，选择确认方式：

* `auto`：默认值。Shell 开启 bracketed paste 模式时直接粘贴；其他情况下，单条命令只带末尾换行或空白时先移除末尾内容，其余多行文本要求确认。
* `always`：文本包含换行就要求确认，包括 Shell 已开启 bracketed paste 的情况。
* `never`：关闭多行粘贴确认。

确认框只预览文本开头，不是全部内容：

* **粘贴**：发送原文。
* **粘贴为一行**：只移除回车和换行，保留已有空格和 `Tab`，不会在原来换行的位置补空格。合并后可能改变命令含义。
* **取消** 或 `Escape`：不发送文本。

勾选 **不再询问** 并接受粘贴后，会把此设置改为 `never`；取消不会保存这个选择。粘贴前核对完整文本、当前目录和活动程序，不要把未出现确认框或已移除换行当作命令安全的保证。

## 配置自动回复

对于重复且含义明确的终端提示，可以使用 `terminal.integrated.autoReplies` 自动发送固定回复。它默认没有规则；只有确认匹配内容和回复都适合当前运行程序时才添加。

1. 在[用户设置](/docs/configure/settings.md#在-json-中编辑)中找到该设置，并在 JSON 中编辑。
2. 在它的对象中，以需要精确匹配的输出文字为键，以要发送的回复为字符串值。回复中的 `\r` 表示按下 `Enter`；不包含它时只发送文本。
3. 保存设置，并在可安全重试的程序中检查实际回复。将某条规则的值设为 `null` 可禁用它。

规则匹配原始终端输出中的文字，不使用正则表达式；每条规则每秒最多回复一次。修改会应用到正在运行的终端，面板隐藏时也可能回复。不要使用过短、容易重复出现的提示，也不要用它自动接受付款、删除或权限确认。规则最多 `32` 条，消息和回复各不超过 `4 KiB`，总量不超过 `64 KiB`。

自动回复保存在设置中，不适合存放密码、令牌或其他秘密。

## 滚动和选择终端输出

先聚焦要查看的终端，再使用以下命令或默认快捷键。滚动只浏览仍保留的屏幕和回滚内容，不会向 Shell 发送输入；已退出和只读终端也可以使用。

| 命令 | Windows | Linux | macOS |
| --- | --- | --- | --- |
| **终端：向上滚动（行）** | `Ctrl+Alt+PageUp` | `Ctrl+Shift+Up` | `Command+Alt+PageUp` |
| **终端：向下滚动（行）** | `Ctrl+Alt+PageDown` | `Ctrl+Shift+Down` | `Command+Alt+PageDown` |
| **终端：向上滚动（页）** | `Shift+PageUp` | `Shift+PageUp` | `PageUp` |
| **终端：向下滚动（页）** | `Shift+PageDown` | `Shift+PageDown` | `PageDown` |
| **终端：滚动到顶部** | `Ctrl+Home` | `Shift+Home` | `Command+Home` |
| **终端：滚动到底部** | `Ctrl+End` | `Shift+End` | `Command+End` |
| **终端：全选** | 从命令面板运行 | 从命令面板运行 | `Command+A` |
| **终端：清除选区** | `Escape` | `Escape` | `Escape` |

滚动命令和快捷键只用于普通输出缓冲区。进入使用备用缓冲区的全屏终端程序时，这些按键继续交给程序。全选包括仍保留的屏幕和回滚内容，不会找回已截断的输出；清除选区不删除内容。查找打开时，`Escape` 保留关闭查找的行为。

Linux 和 Windows 的 `Ctrl+A` 仍交给 Shell，不用作终端全选。Linux 的 `Ctrl+U` 也继续由 Shell 处理，不会触发代码编辑器的光标撤销。快捷键被修改或被操作系统拦截时，可以从命令面板运行，或在[键盘快捷方式](/docs/configure/keyboard-shortcuts.md)中检查绑定。

## 查找终端输出

1. 选择要搜索的终端，并把焦点放入终端。
2. 按 Windows、Linux 的 `Ctrl+F`，macOS 的 `Command+F`，或运行命令 **终端：聚焦查找**。
3. 输入文字，按需打开 **区分大小写**、**全字匹配** 或 **正则表达式**。
4. 使用查找框中的上一个、下一个按钮切换结果。输入框中按 `Enter` 查找下一个，按 `Shift+Enter` 查找上一个。
5. 按 `Escape` 关闭查找并返回终端。

查找覆盖当前实例保留的屏幕内容和回滚缓冲区，不会把搜索文字作为 Shell 命令执行。各实例保留自己的查询和选项。

输出缓冲区有容量限制，不能把终端面板当作完整日志存档。需要保留完整结果时，使用对应命令支持的日志文件选项，或按所用 Shell 的方式把输出写入文件。

## 从输出打开文件、目录和链接

编译器或测试输出中的文件路径可以作为导航入口，例如 `src/main.rs:42:8`。

1. 聚焦需要查看的终端，运行 **终端：打开检测到的链接…**（**Terminal: Open Detected Link…** ），或按 `Ctrl+Shift+O`（macOS：`Command+Shift+O`）。
2. 在列表中搜索文件、目录路径或网址，核对路径和工作目录。已获准提供终端链接的扩展也可以向列表添加链接。
3. 选择文件并按 `Enter`，在编辑器中查看对应行列；选择该终端工作区根内的目录，会在 **Explorer** 中定位并聚焦它。按 `Escape` 取消并回到终端。

也可以使用输出中可识别的文件链接。相对路径优先按产生该输出的命令目录解析；没有命令目录信息时，使用终端已知目录或启动目录。SSH 终端中的文件属于远端，不会自动改为本机同名文件。

相对路径或文件名未直接找到文件时，Ash 会在该终端所属的工作区根内搜索。未达到搜索上限且只有一个匹配时直接打开；多个匹配或搜索结果达到上限时，显示第二个列表，核对完整路径后再选择。搜索不会跨到其他工作区根。

目录链接仍需能读取到实际目录。本地目录位于该终端的工作区根外时，桌面宿主会尝试用新窗口打开，不会向当前工作区添加根。浏览器入口不支持这条新窗口路径；远端根外目录也不能按本机路径打开。

在设置中搜索 `terminal.integrated.enableFileLinks`，可选择 `on`（默认，启用内置文件链接）、`off`（停用）或 `notRemote`（仅本地工作区）。这个设置不关闭网址链接。`terminal.integrated.wordSeparators` 同时控制终端选词和文本文件链接的分词。

无法打开时，先确认文件仍存在、当前环境有读取权限，以及路径所依据的目录是否正确。链接列表从仍保留的输出产生，只有选择需要解析的相对路径或文件名时才搜索对应工作区。网址仍按当前网页打开规则处理。

## 带着终端输出询问 Chat

1. 选择需要分析的终端，先检查输出中是否有密码、令牌或不应发送的内容。
2. 运行 **终端：询问 Chat**（**Terminal: Ask Chat**），输入想了解的命令或报错。
3. 回到 Chat，检查草稿中的问题和终端快照，再自行发送。

这个入口把当时的终端上下文追加到现有 Chat 草稿，不会自动提交问题或执行命令。输入问题时按 `Escape` 取消；期间切换终端或 Chat 会话也会取消交付。接受后的快照不会跟随终端继续更新，关闭源终端也不会改写它。具体的上下文检查和移除方法见[提供有效上下文](/docs/agents/overview.md#提供有效上下文)。

## 清空、关闭和重新启动

这几个操作有不同效果：

* **清空终端**：清空当前屏幕缓冲内容，保留 Shell 进程。可从终端标题栏的更多操作中选择。
* **终止终端**：结束并移除当前实例。其他实例保留；通过标题栏终止最后一个实例时，面板会隐藏。
* 列表中的垃圾桶：关闭该列表项对应的终端。
* **重新启动终端**：替换为新的 Shell 进程，可用于终端退出、断开或出错后恢复，也可用于应用新的启动设置和扩展环境。原 Shell 中尚未完成的命令不会继续执行。

只想暂时离开时，隐藏面板即可。终止或重新启动前，先确认没有需要保留的前台任务。重新启动后，要重新检查目录，并按需要再次运行项目命令。

### 向前台命令发送信号

要中断当前前台程序，可以先在终端没有文本选区时按 `Ctrl+C`。需要选择进程信号时，聚焦目标终端，运行 **终端：发送信号**（**Terminal: Send Signal**）：

* `SIGINT`：请求中断命令。
* `SIGTERM`：请求程序正常结束。
* `SIGKILL`：强制结束，程序没有机会保存或清理。
* `SIGHUP`：发送挂断信号，具体处理取决于程序。

选择后按 `Enter` 立即发送；选择期间按 `Escape`、切换终端或断开连接会取消。macOS 和 Linux 执行端把信号发给当前前台进程组；Shell 自己处于前台时，信号也可能结束 Shell。

Windows 执行端目前不支持此进程信号入口，会报告不支持；这与通过键盘发送 `Ctrl+C` 不同。判断平台时以终端实际运行所在的执行端为准。

### 为运行中的命令开启关闭保护

在设置中搜索以下设置 ID：

* `terminal.integrated.confirmOnKill`：关闭带有子进程的终端前询问。默认 `editor` 只保护编辑区终端；选择 `panel` 保护面板终端，`always` 保护两处，`never` 关闭此提示。
* `terminal.integrated.confirmOnExit`：关闭窗口前询问。默认 `never`；选择 `always` 在存在终端时询问，或选 `hasChildProcesses` 仅在有子进程时询问。

取消关闭提示会保留原终端和进程。保护依赖进程状态，不等于所有命令都可恢复；不要用它代替保存文件。隐藏面板不属于关闭实例。

### 重新加载窗口

桌面应用的 `terminal.integrated.enablePersistentSessions` 默认开启。使用 **Reload Window** 重新加载窗口时，Ash 尝试重新连接原来的本地或 SSH 终端，并恢复屏幕、待提交输入、分屏比例和焦点。

这需要原后端和终端进程仍存活、重连仍有效。扩展自供 PTY 暂不支持这条重载恢复路径；提示无法保留进程时，先处理运行中的任务再重载。

> [!IMPORTANT]
> [故障提示中的 **重新打开**](/docs/support/troubleshooting.md#桌面窗口无响应，或关闭和重载卡住)不同于普通重载。即使终端已准备重载恢复数据，应急重新打开仍可能无法接回原终端，运行中的进程可能结束。优先选择 **继续等待**；恢复后先核对进程和实际文件结果，再决定是否重试命令。

### 退出应用后恢复终端

桌面应用还可以在退出后恢复符合条件的普通交互终端。保持 `terminal.integrated.enablePersistentSessions` 开启，再用 `terminal.integrated.persistentSessionReviveProcess` 选择保存时机：

* `onExit`：默认值。退出应用时保存。Windows 和 Linux 关闭最后一个窗口时也按退出处理；macOS 关闭窗口不等于退出应用。
* `onExitAndWindowClose`：退出应用或关闭单个窗口时保存。
* `never`：不在退出或关闭窗口后重建 Shell；不改变已开启的窗口重载重连。

再次打开对应工作区时，Ash 尝试恢复已保存的输出、工作目录和分屏布局，并创建新的 Shell 进程。恢复不会继续原来的运行中命令，也不会重新执行任务或历史命令。屏幕上的旧输出不能证明服务仍在运行；检查新提示符和目录后，再按需要启动服务或测试。

Windows 终端恢复后，旧输出可能位于当前提示符上方的回滚区。向上滚动，或使用[终端查找](#查找终端输出)定位已保存的内容。

恢复保留原 Shell 的启动命令、参数和环境覆盖，并重新应用当前设置和扩展环境配置。已退出、只读和扩展自定义终端不参加这类恢复。同一工作区的多个桌面窗口分别保存终端状态；是否自动重开这些窗口还取决于[窗口恢复设置](/docs/editing/workspaces.md#选择启动时恢复哪些窗口)。这条路径需要退出时成功保存状态，不保证崩溃或后端重启后恢复。

> [!IMPORTANT]
> 退出恢复会把终端输出和启动信息写入本机状态存储，参数或环境覆盖中也可能有敏感内容。处理这类内容前，可以将 `terminal.integrated.persistentSessionReviveProcess` 设为 `never`，关闭之后的退出恢复。它不关闭窗口重载重连，也不表示先前保存的数据已删除。

## 录制终端排障信息

需要向维护者提供可复现的输入输出记录时，可以使用 **开发人员：录制终端会话**（**Developer: Record Terminal Session**）：

1. 运行该命令。Ash 会创建专用的新终端，并在状态栏显示正在录制。
2. 在新终端中复现问题，避免输入秘密或运行无关命令。
3. 选择状态栏的录制提示停止，并把生成的 JSON 从剪贴板粘贴到你准备检查的文件中。

连续 `5` 秒没有录制活动时会自动停止；终端退出或输入、操作记录达到限制时也会停止。录制包含输入、输出、操作记录和尺寸变化，输出较多时可能被截断，不能代替完整日志或会话备份。

> [!IMPORTANT]
> 录制会捕获终端输入，即使密码等内容没有显示在屏幕上，也可能进入记录。分享前检查并删除密码、令牌、私有路径和其他敏感内容；不要把原始记录直接粘贴到公开问题中。

## 排查常见问题

### 提示先打开文件夹

看到 `Open a folder to use the terminal.` 时，先打开工作区文件夹，再聚焦终端。普通 Shell 终端需要工作区目录。

### 提示终端不可用或文件夹受限

先确认当前窗口已打开项目文件夹，并检查后端或远程连接是否正常。终端还需要目标目录的运行命令权限；只读目录不具备这项权限。

打开目录时，若出现权限选择，核对路径和项目来源，再决定选择 **信任文件夹并启用开发功能**，还是 **以只读模式打开**。后者仍可浏览、搜索和查看仓库，但不能启动终端。已有授权时不一定会再次弹出选择，重新打开文件夹也不保证会更改权限。

当前部分终端错误仍显示含有 **Trust the folder** 或 **Restricted Mode** 的提示；未打开文件夹也可能触发同一提示。不要仅凭这段文案判断需要扩大权限，先按[打开和管理项目](/docs/editing/workspaces.md)检查目录与具体权限。

### 命令退出后终端仍然显示

Shell 退出时，Ash 会保留实例和输出，方便检查错误。需要继续时选择 **重新启动终端**，或者关闭该实例后新建终端。

### 连接中断后不能输入

桌面应用中的本地和 SSH 终端会先尝试重连到原进程，恢复读取后才能继续使用。同一后端的重连保留窗口为 30 秒；后端重启、租约过期或执行环境被替换后，原进程不能按这条路径恢复。

如果恢复失败，查看错误再选择 **重新启动终端**。它创建新进程，不会继续原命令。浏览器入口的普通后端终端不提供相同的桌面重连保证。不要重复输入命令来猜测连接是否恢复；断线期间未完成的输入不会在恢复后自动重放。

### 查找不到很早以前的输出

查找只搜索当前还保留的内容。已经被截断或清空的内容无法通过查找恢复。需要完整记录时，查看命令写入的日志文件。

### 找不到拆分或默认配置入口

打开加号旁的菜单，查找 **拆分终端**、**使用配置拆分终端** 和 **选择默认配置**，也可以从命令面板查找。拆分需要可写、正在运行的普通 Shell；面板和编辑区都支持，扩展自定义终端或连接未就绪时不能使用。默认配置选择器以执行环境中实际可用的 Shell 为准。
