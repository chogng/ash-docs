# 运行和配置任务

任务把项目中的构建、检查和测试命令保存为可重复运行的操作。本指南介绍如何运行任务、配置执行目录和终端布局，以及在确认项目可信后启用打开文件夹时的自动任务。

这些任务在项目的执行环境中启动进程。先安装所需的运行时和依赖，并确认项目目录有运行命令的权限。本文依据当前源码，已发布安装包的功能以实际版本为准。

## 运行已有任务

1. 打开项目文件夹。
2. 打开命令面板，运行 **运行任务**（**Run Task**）。也可以在终端加号旁的菜单中选择 **运行任务...** 。
3. 在快速选择器中核对任务名称、来源和详细信息，选择要运行的任务。详细信息可以是任务说明或命令。运行陌生任务前，先检查配置中的实际命令。
4. 查看终端输出和任务状态。任务可以配置为不自动显示终端。

Ash 会发现 `.vscode/tasks.json` 中版本为 `2.0.0` 的任务、`package.json` 中的脚本，以及存在 `Cargo.toml` 时的常用 Cargo 命令。任务选择器会随任务配置刷新，输出保留在终端中。打开列表本身不会执行命令，但已启用的自动任务可以在符合条件时启动。

按 `Escape` 取消选择。没有可运行任务时，Ash 会转入 **配置任务...** 流程。需要按类别查找时，运行 **运行生成任务**（**Run Build Task**）或 **运行测试任务**（**Run Test Task**）。这两项使用任务的 `group` 分类；只有一个匹配的默认任务时会直接运行。

使用 **重新运行上一个任务**（**Rerun Last Task**）再次执行最近的任务。默认会重新计算变量；任务设有 `runOptions.reevaluateOnRerun: false` 时保留上次已解析的变量值。普通 **运行任务** 仍会重新计算变量。

要停止进程，运行 **终止任务**（**Terminate Task**）。有多个运行中的任务时，先选择目标。任务完成后通常保留终端输出，方便查看退出代码；仅隐藏面板不会停止任务。

## 添加项目任务

可以从配置入口打开文件或创建模板：

1. 运行 **配置任务...** （**Configure Tasks...** ），或从终端加号旁的菜单选择该项。
2. 如果出现任务列表，选择要配置的任务，或选择 **从模板创建 tasks.json 文件**。
3. 在多根工作区中，检查目标目录。选择已有任务时使用任务所属根。未确定目录时，选择要保存配置的工作区文件夹。
4. 如果该目录已有 `.vscode/tasks.json`，Ash 会直接打开并保留其内容。文件不存在时，选择已有任务会生成它的配置；选择模板流程则从 **npm**、 **.NET Core**、**TypeScript** 或 **其他** 中选择一项。
5. 检查文件中的命令、参数和目录，按项目需要修改并保存，再使用 **运行任务** 执行。

取消任务、文件夹或模板选择不会创建配置文件。模板只提供可编辑的示例，不会安装依赖或自动运行其中的命令。若已有 `tasks.json`，请在原文件中添加任务，不要覆盖现有任务和注释。

也可以直接在项目根目录创建或编辑 `.vscode/tasks.json`。下面的示例需要执行环境已安装 Node.js，两个任务分别显示版本和工作目录：

```json
{
  "version": "2.0.0",
  "tasks": [
    {
      "label": "检查 Node 版本",
      "type": "process",
      "command": "node",
      "args": ["--version"],
      "options": { "cwd": "${workspaceFolder}" },
      "presentation": { "panel": "new", "group": "checks" }
    },
    {
      "label": "显示项目目录",
      "type": "process",
      "command": "node",
      "args": ["-p", "process.cwd()"],
      "options": { "cwd": "${workspaceFolder}" },
      "presentation": { "panel": "new", "group": "checks" }
    }
  ]
}
```

保存后，分别从 **运行任务** 选择这两个任务。你应能看到 Node.js 版本和项目目录，两个输出位于同一终端组的分屏窗格中。

* `label`：任务选择器中的名称。
* `type: "process"`：直接启动程序，`args` 中每个字符串作为独立参数传入。它不通过 Shell 解释管道或重定向。
* `type: "shell"`：使用 Shell 执行命令。命令语法必须适合实际执行环境中的 Shell。
* `options.cwd`：任务工作目录。`${workspaceFolder}` 指向任务所属的工作区文件夹。
* `options.env`：为本次任务设置环境变量，值为字符串；使用 `null` 删除继承的变量。它不会更改以后新建的普通终端环境。

在多根工作区中，将任务放在对应根目录的 `.vscode/tasks.json` 中。不要把另一个根目录的相对路径当作当前任务目录。`windows`、`osx` 和 `linux` 配置块依据命令执行端的系统选择，而非浏览器所在设备的系统。

任务可以使用 `${selectedText}` 读取执行时捕获的编辑器选区。选中文本原样插入，其中类似 `${command:...}` 的文字不会触发额外的 Ash 变量解析；Shell 任务仍会按 Shell 语法解释最终命令。只需要把文本交给程序时，优先使用进程任务的独立参数。

## 控制任务终端和分屏

`presentation.group` 将同一工作区文件夹中具有相同非空组名的任务终端放进一个分屏组。上例使用 `checks`。这个字段控制布局；任务顶层的 `group: "build"` 或 `group: "test"` 用于生成和测试分类。

`presentation.panel` 控制是否复用任务终端：

* `shared`：默认值。复用同一工作区文件夹、相同分屏组中的空闲任务终端。
* `dedicated`：只复用该任务自己的空闲终端。
* `new`：每次运行创建新终端。有相同 `presentation.group` 时，新终端仍加入该分屏组。

同时运行的任务使用不同终端。复用会启动新进程并应用本次目录和环境；默认保留屏幕输出，设置 `presentation.clear: true` 会先清空。拖动窗格间的分隔线调整大小，也可以用 **终端：聚焦下一窗格** 和 **终端：聚焦上一窗格** 切换焦点。

按需配置输出显示：

* `presentation.reveal`：默认 `always` 显示终端；`silent` 在错误诊断或失败退出时显示；`never` 不自动显示。
* `presentation.focus`：设为 `true` 时，在显示终端时移入焦点。它不会覆盖 `reveal: "never"`。
* `presentation.close`：设为 `true` 时，在任务结束并释放进程后关闭该终端。需要保留结果时，不要开启。

## 打开文件夹时自动运行

自动任务默认关闭。任务配置和用户允许缺一不可：项目用 `runOptions.runOn: "folderOpen"` 标记任务，你再通过用户设置允许受信任的工作区自动运行。项目文件不能自行开启这项用户设置。

1. 先检查任务命令、依赖任务和项目来源，并手动运行确认结果。
2. 在需要自动运行的任务对象中加入以下字段并保存：

   ```json
   "runOptions": { "runOn": "folderOpen" }
   ```

3. 确认工作区可信且具有运行命令权限。启用自动任务不会授予目录权限。
4. 打开命令面板，运行 **管理自动任务**（**Manage Automatic Tasks**），选择 **允许自动任务**。

此操作把应用级用户设置 `task.allowAutomaticTasks` 改为 `on`，适用于受信任的工作区。也可以在设置中搜索该 ID；默认值为 `off`。

> [!IMPORTANT]
> 在已经打开的受信任工作区中启用后，符合条件的任务会立即启动。以后打开工作区或重新加载窗口也可能再次运行，因此不要把必须逐次确认的发布、删除或付款命令设为自动任务。

同一次进入工作区时，已经启动的自动任务不会因刷新任务列表或信任状态通知而重复启动。要关闭自动运行，再次执行 **管理自动任务** 并选择 **禁止自动任务**。

禁用会取消尚未完成的启动准备，不会停止已经运行的任务。需要停止现有进程时，另外使用 **终止任务**。

## 排查任务未启动

* **没有列出任务而进入配置流程**：检查任务文件的位置、`version` 和 `tasks` 数组，保存后重新打开 **运行任务**。该命令会重新发现任务。
* **提示不支持某项配置**：按错误列出的字段修改任务，再运行。能列出任务不代表所有 VS Code Tasks 配置都已受支持；已知不支持的执行选项会在创建终端前被拒绝。
* **提示无法为 Shell 引用结构化参数**：当前 Shell 不在受支持的结构化引用类型内。Ash 支持识别出的 POSIX Shell、Fish、PowerShell 和命令提示符；Nushell 或 WSL 启动器不能假定使用 POSIX 引用。可以改用 `process` 任务，或把适合所选 Shell 的完整命令行写入字符串 `command`，不另设 `args`。
* **自动任务没有启动**：依次检查 `runOn`、`task.allowAutomaticTasks`、工作区信任和目录执行权限。仅把 `runOn` 加入项目文件不会开启自动执行。
* **连接中断**：检查连接与终端状态，确认命令是否已产生结果，再决定是否重跑。不要把重新连接当作任务自动重试。
