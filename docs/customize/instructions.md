# 为项目设置指令

把项目约定保存为指令，可以减少每次聊天都要重复说明的内容。适合保存的内容包括目录职责、测试入口、代码约定和不能破坏的兼容性要求。针对一类任务的多步工作流程，可以使用 [Skills](/docs/customize/skills.md)。

本页先创建一份项目指令，再把只适用于部分文件的规则拆开，最后检查规则是否按预期生效。

## 选择文件位置

项目指令以当前会话已获授权的目录为范围。通常把项目根目录选为工作目录；不要把“磁盘上存在文件”当成该目录已经获得访问授权。

| 用途 | 项目位置 | 加载方式 |
| --- | --- | --- |
| 多种 Agent 共用的项目约定 | 项目根目录的 `AGENTS.md` | 在该目录范围内持续加载 |
| Ash 专属的项目约定 | 项目根目录的 `ASH.md` | 在该目录范围内持续加载 |
| 按主题拆分的规则 | `.ash/instructions/<name>.md` | 由 `load` 字段决定 |
| 子目录专用的约定 | 子目录中的 `AGENTS.md` 或 `ASH.md` | 本轮成功读取该子目录下的文件后加载 |

`AGENTS.md` 和 `ASH.md` 使用普通 Markdown，不需要 YAML 文件头。`.ash/instructions/` 中的文件必须带文件头，而且只读取该目录直接包含的 `.md` 文件，不递归扫描下一级文件夹。

## 创建第一份项目指令

1. 在 Ash 中打开项目，并确认当前会话可以读取该目录。
2. 在聊天输入框中输入 `/init` 并提交。也可以明确输入 `/init workspace`。
3. Ash 会检查项目结构、构建与测试入口以及已有的 `AGENTS.md`，然后创建或更新项目根目录的 `ASH.md`。写入仍遵循当前权限和批准方式。
4. 打开生成的文件，核对命令、路径和约定。删除占位文字、错误假设和与 `AGENTS.md` 重复的内容。
5. 用一个小任务验证结果，再把需要团队共享的文件纳入版本控制。

`/init` 的目标是 `ASH.md`。它不会把已有的共享 `AGENTS.md` 当作需要替换的文件。

也可以手动创建 `ASH.md`。例如：

```markdown
## 工作约定

- 修改功能前，先阅读相关模块已有的测试和错误处理方式。
- 不改动与当前任务无关的文件。
- 为行为变化补充回归测试。
- 完成后说明实际运行的检查，以及没有运行的检查和原因。
```

把通用要求替换或补充为项目的真实约定。例如记录准确的测试命令，而不是写“运行所有必要测试”。

## 为特定文件添加规则

当一条规则只适用于某种语言或模块时，创建 `.ash/instructions/<name>.md`，避免每个任务都加载无关内容。

1. 在项目根目录创建 `.ash/instructions/`。
2. 新建 `typescript-tests.md`，使用 UTF-8 编码和 LF 换行。
3. 写入以下内容，并按项目实际情况调整匹配范围和规则。

```markdown
---
name: typescript-tests
description: 修改 TypeScript 测试时使用的测试组织和异步清理约定。
load: contextual
patterns:
  - "**/*.test.ts"
---

- 优先沿用相邻测试的断言和 mock 方式。
- 每项测试结束后清理创建的定时器和订阅。
- 异步操作需覆盖取消和失败路径。
```

4. 保存后，让 Ash 先读取一个匹配的测试文件，再完成一个小的测试修改。
5. 检查生成的测试和实际执行的验证步骤，而不只检查回复是否提到了规则。

`patterns` 是相对作用域根目录的 glob 列表。当前的自动匹配依据是本轮已经成功读取、且仍处于授权范围内的文件路径；只在消息中提到文件名，并不会触发匹配。

Ash 使用 `patterns`，不是 VS Code 指令文件的 `applyTo`。不要把其他产品的文件头原样复制进来。

## 选择加载方式

`.ash/instructions/*.md` 的 `load` 必须是以下三种值之一。

| 值 | 适用场景 | `patterns` |
| --- | --- | --- |
| `global` | 该作用域每次模型调用都需要的规则 | 不填写 |
| `contextual` | 只与特定文件有关的规则 | 必须有至少一项 |
| `on-demand` | 偶尔使用、需要时再选取的规则 | 不填写 |

`name` 可省略；填写时必须与文件名去掉 `.md` 后的部分一致。文件名使用小写字母、数字和连字符，不能以连字符开头或结尾，最长 64 个字符。建议填写简短的 `description`，说明何时需要这份规则。

按需规则示例，保存为 `.ash/instructions/release-check.md`：

```markdown
---
name: release-check
description: 准备发布前检查变更说明和已完成的验证。
load: on-demand
---

- 对照本次实际改动检查变更说明。
- 明确列出已通过、失败和未运行的检查。
- 不把准备发布材料视为已经获准发布。
```

`description` 用于帮助 Agent 判断相关性，不会单凭描述把整份正文加入每次调用。Agent 可以在需要时读取规则，也可以由你显式附加。

## 在聊天中附加一份指令

在桌面工作台中，可以为当前任务显式选择已发现的指令：

1. 在聊天输入框旁选择 **Add context**。
2. 选择 **Instructions…**。
3. 按名称、描述或路径搜索，核对条目的 **User** 或 **Directory** 范围。
4. 选择指令，补充具体任务后发送。

发送时，Ash 会重新检查该指令是否仍在当前会话的授权目录中。已删除、格式无效或不再有权访问的文件不能继续作为有效指令附加。

选择列表用于发现和附加文件，不是逐轮执行记录。看到一条指令，也不表示当前任务已经使用或遵守它。当前没有独立的指令启停管理面板。

## 在多个项目使用个人指令

个人指令放在当前运行环境选定的 Ash home 中。默认是用户主目录下的 `.ash`；设置 `ASH_HOME` 时，以该绝对目录为准。

| 用途 | 位置 |
| --- | --- |
| 个人共享约定 | `<Ash home>/AGENTS.md` |
| 个人 Ash 约定 | `<Ash home>/ASH.md` |
| 个人分主题规则 | `<Ash home>/instructions/<name>.md` |

例如默认位置是 `~/.ash/instructions/response-style.md`，不再额外嵌套一层 `.ash`。个人规则目录同样只扫描直接 `.md` 文件。

可以输入 `/init user` 创建或更新当前 Ash home 下的 `ASH.md`，也可以使用内置 Skill：

```prompt
$create-instructions 把“完成后说明已运行和未运行的检查”保存为本项目的持续规则。先检查已有规则，避免重复。
```

远程会话的路径属于当前连接的运行环境。不要只在另一台机器的同名目录中创建文件，再假定它会同步生效。

## 理解范围和冲突

指令帮助 Ash 理解如何工作，不能增加工具、文件、网络或批准权限。

在系统、安全和工具权限约束内：

- 当前用户的明确请求优先于持久化指令。
- 个人指令优先于目录指令。
- 目录规则只适用于自己的目录范围。
- 子目录规则和 `ASH.md` 可以细化局部约定，但不能默默取消父目录的明确限制。
- 同一作用域的冲突没有“文件名排在后面就覆盖”的规则。应修改冲突的原文；冲突阻碍任务时需要澄清。

嵌套的 `AGENTS.md` 和 `ASH.md` 在本轮读取相关文件后按浅到深加入，不会事先扫描项目的所有子目录。不要用一个子目录的规则约束无关目录。

文件修改或删除会在下一次模型调用时重新检查。当前规则以当时仍有效的文件和授权范围为准，历史消息中的旧副本不会恢复已经撤销的权限。

## 检查与排错

先用一个小而明确的任务验证规则。例如要求 Ash 读取一份测试文件，再为一个失败路径补测试，并检查它是否遵循了文件中的清理要求。

| 现象 | 检查方式 |
| --- | --- |
| 找不到指令 | 检查当前工作目录、访问权限、文件位置和大小写；多文件规则必须直接位于 `.ash/instructions/` |
| 新规则没有生效 | 确认文件已保存；等待下一次模型调用，或启动一个新任务复测 |
| 文件特定规则没有加载 | 确认本轮确实成功读取了匹配文件；聊天中的路径文字或编辑器打开状态不足以触发 |
| 指令格式报错 | 检查文件开头的 `---`、UTF-8、LF 换行、`load` 值，以及 `name` 是否与文件名一致 |
| `global` 或 `on-demand` 报错 | 删除 `patterns`；只有 `contextual` 可以且必须填写它 |
| 从其他工具复制后无效 | 转换为 Ash 字段和目录；原生加载器不会自动扫描 `.github/`、`.claude/`、`.codex/` 或 `.agents/` 的专有指令格式 |
| 修改文件前提示先读取规则 | 让 Ash 先读取提示中的适用指令，重新检查方案，再提交新的文件修改 |
| 回复说读过规则，但结果不符合 | 核对实际改动与测试；成功读取只证明内容可用，不保证每项要求都被遵守 |

每个指令文件上限为 32 KiB；分主题规则目录最多检查 128 个直接条目。单个 `contextual` 文件最多包含 32 条 pattern，每条最多 256 字节。使用真实文件和目录，不要用符号链接代替它们。

原生文件修改工具会在修改前检查适用规则，包括新建文件；任意 Shell 程序的写入不在这项检查覆盖范围内。指令不是替代代码审查或测试的强制安全机制。
