# 开始第一个任务

本教程带你完成一次简单的工作流程：打开项目、准备模型、理解代码，然后修改和检查结果。建议使用可以安全试验的项目，并先保存已有工作。

## 开始之前

你需要已能运行的 Ash 桌面应用或 Ash Code，以及所选模型供应商的有效凭据。模型出现在列表中不代表请求一定可以成功；还需要可用的账号、服务连接和供应商配置。

如果尚未运行应用，先阅读[从源码运行 Ash](/docs/getstarted/run-from-source.md)。

## 1. 打开要处理的项目

在桌面应用中打开项目文件夹。如果已安装 Ash Code，也可以在终端进入项目目录，再运行：

```sh
ash
```

先确认工作目录正确，再开始会话。不要在不熟悉的目录里直接要求批量修改。

## 2. 选择模型并让它理解项目

配置模型供应商并选择可用模型。发送一个只读任务：

```text
解释这个项目如何启动，主要功能在哪里，以及怎样运行测试。
请根据实际文件回答，列出依据，暂时不要修改代码或运行安装命令。
```

查看回复引用的文件和工具活动。你应当能找到项目的入口和测试方式；如果请求失败，先核对模型配置、凭据和网络错误。

## 3. 给出一项具体修改

选择你已经观察到的小问题，描述复现步骤、期望结果和修改范围。例如：

```text
设置页保存后，界面仍显示旧值。请先复现并找到原因，修复这个问题，
补上回归测试。不要顺带重构其他模块。完成后说明修改和验证结果。
```

这是任务描述示例，不表示你的项目一定存在这个问题。把它替换成你自己的场景。

## 4. 检查需要批准的操作

执行过程中，关注文件修改、命令运行和外部工具调用。遇到批准请求时，阅读具体动作、目标和访问范围，再决定是否允许。

不确定时可以拒绝并补充要求。已经执行的操作不会因为后来拒绝而自动撤销。详见[权限与批准](/docs/configure/permissions.md)。

## 5. 检查结果，再继续

完成后检查三个方面：

- 修改是否解决了你描述的问题，是否包含无关文件。
- 相关测试是否真的运行，哪些通过、失败或未运行。
- 是否还需要在实际应用里重复原来的操作确认结果。

有遗漏就在同一会话补充。处理无关的新目标时再新建会话。不要只凭 Agent 的完成说明就提交或发布。
