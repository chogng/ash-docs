# 调试程序

在 Ash Code 的 **运行和调试** 侧栏中，你可以启动程序，在断点处暂停，检查变量，再逐步执行。开始前需要一个已安装、能通过标准输入输出通信的 DAP 调试适配器，以及项目的 `.vscode/launch.json`。Ash 不会仅凭语言名称自动安装调试器。

本文适用于具备调试执行能力、已连接运行环境的 Code 工作台。Academic 不提供这组调试功能。示例使用真正的 LLDB-DAP，前提是运行环境已具备下面列出的工具；本页不代表这些工具随 Ash 一起安装。

## 准备调试适配器

调试适配器连接 Ash 与具体语言的调试器。先确认三件事：

1. 已在 Ash 中打开项目文件夹，当前环境允许读取项目的可执行配置和执行进程。只运行你信任的配置。权限说明见[目录与执行权限](/docs/configure/permissions.md)。
2. 当前运行环境中已有适合项目的 **stdio DAP 适配器**，并且知道它的可执行文件位置及启动参数。普通语言运行时或调试器命令不一定就是 DAP 适配器。
3. 待调试程序及其依赖已准备好。编译型项目还需要带调试信息的可执行文件；修改源码后应重新构建。

本地项目使用本地环境中的工具。SSH Remote 项目使用远端的适配器、程序和路径；本机安装的工具不能替代远端工具。

配置适配器有两条路径：

- 在 `launch.json` 中明确填写 `debugAdapter.program` 和可选的 `debugAdapter.args`。下面使用这种方式。
- 已安装的扩展通过声明式 `contributes.debuggers` 提供对应 `type` 时，可以省略 `debugAdapter`。这不表示 Ash 能运行任意 VS Code 调试扩展的 JavaScript，也不保证复制其配置就能使用。

## 创建 launch.json

1. 打开侧栏的 **运行和调试**（Run and Debug）。
2. 尚未打开文件夹时，选择 **打开文件夹**。已有文件夹但没有配置时，选择 **创建 launch.json 文件**。
3. Ash 创建含空 `configurations` 数组的 `.vscode/launch.json`。已有文件会直接打开，不会覆盖。它不会生成语言配置或下载适配器。
4. 填入适合当前项目的配置并保存。之后可以用侧栏的 **打开 launch.json** 按钮返回此文件。

多文件夹工作区会读取各文件夹中的 `.vscode/launch.json`，并在配置名称旁显示所属文件夹。创建配置时优先使用当前编辑文件所属的工作区文件夹，否则使用第一个文件夹；先确认文件保存的位置。

### 示例：用 LLDB-DAP 调试一个 C 程序

以下示例面向 macOS 或 Linux，要求项目所在环境已经安装 `clang` 和 `lldb-dap`，并允许启动调试进程。`lldb-dap` 必须能被 Ash 的执行环境找到；如果不能，使用其实际绝对路径替换配置中的 `"lldb-dap"`。

在项目根目录创建 `debug-hello.c`：

```c
#include <stdio.h>

int main(void) {
    int answer = 40;
    answer += 2;
    printf("answer=%d\n", answer);
    return 0;
}
```

在该项目的[集成终端](/docs/terminal/basics.md)中编译：

```sh
clang -g -O0 debug-hello.c -o debug-hello
```

命令成功后，项目根目录应有 `debug-hello`。若编译器或适配器不存在，先按相应工具的说明准备环境；下面的 JSON 不会安装它们。

把以下配置保存到 `.vscode/launch.json`：

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "调试 C 示例",
      "type": "lldb-dap",
      "request": "launch",
      "debugAdapter": {
        "program": "lldb-dap",
        "args": []
      },
      "program": "${workspaceFolder}/debug-hello",
      "args": [],
      "cwd": "${workspaceFolder}",
      "stopOnEntry": false
    }
  ]
}
```

两个 `program` 含义不同：`debugAdapter.program` 是适配器，外层 `program` 是交给 LLDB-DAP 调试的可执行程序。相应的两个 `args` 也分别传给适配器和目标程序。

Ash 要求 `version` 为 `0.2.0`，配置包含非空的 `name`、`type`，以及 `launch` 或 `attach` 类型的 `request`。除 Ash 自己处理的配置字段外，其余字段会交给适配器；`program`、`cwd`、`stopOnEntry` 等在此示例中采用 LLDB-DAP 的含义，其他适配器可能使用不同字段。

当前会展开 `${workspaceFolder}` 和 `${workspaceFolderBasename}`，包括适配器命令及其参数中的这两个变量。不要假定 `${file}`、`${env:NAME}`、`${command:...}` 或其他编辑器的变量替换也可用。`attach` 所需的进程标识、端口等参数由对应适配器决定；本例只演示启动程序。

## 设置断点并启动

1. 保存源码并完成编译。在 `debug-hello.c` 的 `answer += 2;` 这一行左侧断点栏单击，或把编辑光标放到该行后按 `F9`。
2. 在 **运行和调试** 顶部的 **调试配置** 下拉框中选择 **调试 C 示例**。
3. 点击下拉框旁的 **启动调试** 按钮。
4. 程序命中断点后，状态显示 **已暂停**。调用堆栈应出现当前函数，编辑器打开对应源码位置，变量区可查看 `answer`。

再次点击断点栏或按 `F9` 可移除该行断点。**断点** 列表中的复选框可临时禁用某个断点；分组工具栏还能启用、禁用或移除所有断点。

断点需要适配器确认后才算已验证。未验证时，查看断点的提示和错误原因；图标存在不代表程序一定会在那里暂停。

`F5` 有一个当前需要注意的区别：会话已暂停时，它继续当前会话；没有已暂停会话时，它刷新配置并启动配置列表中的第一个配置。要启动下拉框选中的其他配置或复合配置，请点击旁边的 **启动调试** 按钮。会话正在运行时也不要用 `F5` 作为暂停键。

### 条件断点与日志断点

在 **断点** 列表中选中某个断点，按 `F2` 或选择 **编辑断点**，可以填写：

- **表达式条件**：例如只在某个值满足条件时暂停。
- **命中次数条件**：达到指定命中条件时暂停。
- **日志消息**：在适配器支持日志断点时输出消息。

按 `Enter` 保存，按 `Escape` 取消。条件语法、命中次数写法及日志插值规则取决于适配器。若适配器不支持某个选项，Ash 会显示原因，并且不会把该断点降级为普通无条件断点发送。

## 单步执行与检查变量

暂停后，可使用侧栏调试工具栏：

| 操作 | 默认按键 | 用途 |
| --- | --- | --- |
| 继续 | `F5` | 运行到下一个断点或程序结束 |
| 暂停 | `F6`，会话运行时 | 请求暂停当前线程 |
| 单步跳过 | `F10` | 执行下一步，不进入函数内部 |
| 单步进入 | `F11` | 尝试进入下一步调用的函数 |
| 单步跳出 | `Shift+F11` | 执行到当前函数返回 |
| 停止 | `Shift+F5` | 结束当前调试会话 |

实际停靠位置由适配器和调试信息决定。若系统占用了功能键，可以使用按钮或[调整快捷键](/docs/configure/keyboard-shortcuts.md)。

在 C 示例的断点处按一次 **单步跳过** 后，程序应移到后面的语句，`answer` 从 `40` 变成 `42`。如果修改了示例值，以当前源码及重新编译后的程序为准。

**调用堆栈** 显示当前线程的栈帧。选择其他栈帧会切换查看的源码位置和变量；有多个线程时，可使用 **调试线程** 下拉框。有多个会话时，先通过 **活动调试会话** 选择目标，避免在另一个程序上单步或停止。

在 **变量** 区域中展开对象以查看子项。适配器支持修改变量、程序已暂停且该变量可写时，可选中变量按 `F2` 或双击，输入新值并按 `Enter` 提交；`Escape` 取消尚未提交的输入。失败时会保留输入并显示原因。

修改变量会改变正在运行的程序。已提交的修改不能靠关闭输入框撤回。继续执行、切换栈帧或切换会话也会结束当前编辑；只读变量和尚未展开的延迟变量不能直接修改。

## 使用监视和调试控制台

### 监视表达式

1. 在 **监视**（Watch）标题栏选择 **添加监视表达式**。
2. 输入表达式并按 `Enter`。在 C 示例中可输入 `answer`。
3. 暂停或切换栈帧后，查看该上下文中的结果。修改变量成功后，监视结果也会刷新。
4. 用表达式旁的移除按钮删除一项，或用 **移除所有表达式** 清空。

监视表达式会按工作区保存；显示的值依赖当前已暂停的会话和栈帧。不要把有副作用的函数调用当作纯粹查看数值，表达式如何执行由适配器决定。

### 调试控制台

打开底部的 **调试控制台**（Debug Console）。找不到面板时，可在命令面板中查找 **聚焦调试控制台视图**（Focus on Debug Console View）。它显示适配器发送的调试输出，与通用输出面板和 Shell 终端分开。

- 有多个调试会话时，选择控制台中的会话。
- 在表达式输入框中输入适配器支持的表达式，按 `Enter` 求值。
- 使用 **Clear Console** 清除当前会话的控制台记录。

控制台是否支持某种表达式、运行时能否求值，都取决于适配器。当前控制台求值没有显式传入侧栏选中的栈帧；检查某个栈帧的局部变量时，优先使用 **变量** 和 **监视**。程序若通过集成终端启动，其交互输入应在对应终端中完成。

隐藏控制台不会停止收集调试输出。会话结束后仍可在当前窗口查看保留内容，但不能继续求值。控制台历史不跨窗口重启保存，最多保留 20 个会话、每会话 128,000 个字符；需要长期保存的日志应由程序另外写入文件。

## 停止、重启和多个目标

选择调试工具栏的 **停止**，或按 `Shift+F5` 结束当前会话。停止后，变量和调用堆栈会清空，断点及监视表达式仍保留。Ash 会向适配器发送断开请求并关闭适配器进程；被调试程序是否终止取决于适配器能力与会话方式。使用 `attach` 时，先了解该适配器的停止行为。

选择 **重启** 可再次调试当前配置。若适配器不支持直接重启，Ash 会停止旧会话再重新启动。重启不会自动重新编译程序，除非你配置了相应启动前任务。

已有多个会话时，可以分别切换和控制；需要全部结束时，使用 **全部停止** 或命令 **停止所有调试**（Stop All Debugging）。切换工作区或失去执行环境连接会结束旧会话，不支持在另一进程中恢复它们。

如果项目已经定义了任务，可在某个调试配置中添加 `preLaunchTask` 或 `postDebugTask`，值为任务引用名称。启动前任务必须成功完成；找不到任务、名称歧义、失败或取消都会阻止调试启动。结束后任务在该会话结束时执行。仅写入任务名称不会创建任务。

要一次启动多个已有配置，可在 `launch.json` 顶层添加 `compounds`，按配置名称引用。把下面的两个名称换成同一文件中已经存在的配置名称：

```json
"compounds": [
  {
    "name": "同时调试两个目标",
    "configurations": ["服务端", "客户端"],
    "stopAll": true
  }
]
```

这是顶层字段片段，需与 `version`、`configurations` 正确组合为一个 JSON 对象。选择侧栏里的复合配置再点击 **启动调试**。`stopAll: true` 表示其中一个会话结束或出错时，其余成员也会停止；启动中失败时，Ash 会停止本次已经启动的成员。

## 排查常见问题

| 现象 | 先检查什么 |
| --- | --- |
| 没有调试入口，或提示主机不提供调试能力 | 确认使用 Code 工作台，且运行环境连接和调试执行能力可用。仅有界面不等于能启动进程。 |
| 配置列表为空 | 打开项目文件夹，检查 `.vscode/launch.json` 已保存、`configurations` 不是空数组，必需字段有效。 |
| 提示缺少 `debugAdapter` | 填入真实适配器命令，或确认已安装的声明式调试器确实提供该 `type`。仅写 `node`、`python` 等名称不会安装调试器。 |
| 找不到可执行文件或启动失败 | 区分适配器与目标程序的两个 `program`；检查对应环境的绝对路径、执行权限、依赖以及编译输出。必要时用适配器的实际绝对路径替代命令名。 |
| 启动前任务阻止调试 | 检查任务存在且引用不歧义，先让任务独立成功完成。 |
| 断点未验证或未命中 | 查看断点提示，确认源码与正在执行的构建匹配、该行可执行、源码路径正确，并检查条件和适配器能力。重新编译后再启动。 |
| 变量区为空 | 确认会话已暂停，选择有调试信息的线程和栈帧。源码无法打开时仍可查看适配器提供的变量，不必把两者视为同一个故障。 |
| 控制台找不到局部变量 | 先检查所选会话，再用已暂停栈帧中的变量或监视查看；控制台不保证跟随侧栏栈帧。 |
| 提示终端不可用，调试命令尚未执行 | 恢复当前环境的终端连接后重新启动调试。该命令不会在终端恢复时自动补发。 |
| SSH Remote 调试找不到文件 | 检查适配器、可执行文件、构建路径和源码都位于当前远端环境，不要填成本机路径。 |

## 当前能力边界

- 支持 stdio DAP 适配器；不支持直接连接 socket/server 形式的适配器。已有 `attach` 请求支持不等于支持这种适配器传输方式。
- 函数断点、变量数据断点、指令断点、异常断点及反汇编都依赖适配器能力。相应入口可以出现在断点区、变量行或调用堆栈工具栏中；不可用时先看提示，不要推断为所有语言都支持。
- 反汇编需要先暂停且适配器支持该能力。反汇编编辑器处于活动状态时，单步会尝试按指令执行，还需适配器支持指令粒度。
- 行断点、函数断点、监视表达式和异常过滤器会保存；数据断点只有在适配器允许时才持久化，指令地址断点只属于当前会话。活动会话、变量值和调用堆栈不持久化。
- 声明式调试器发现不等于完整的 VS Code Debug Extension API 兼容。已有其他编辑器配置需要逐项核对适配器、字段和变量。
