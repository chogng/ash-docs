# 搜索与替换项目内容

使用 Ash 的 **Search** 视图，可以查找工作区多个文件中的文本、按路径缩小范围，并检查批量替换。完成本指南后，你可以从一次搜索定位到代码，再只应用需要的修改。

## 开始之前

先打开项目文件夹。没有打开文件夹时，搜索会显示提示 **Open a folder to search files.**

搜索前保存需要纳入检查的编辑；批量替换前，尤其要检查受影响文件中已有的未保存修改。项目替换会保存受影响文件，这些文件中已有的其他编辑也可能一并保存。建议先确认已有工作，或在版本控制中留下便于比较的基线。

只查找当前文件时，使用[编辑器内的查找与替换](/docs/editing/editing-and-navigation.md)。本文介绍工作区范围的搜索，使用英文界面名称说明入口。

## 运行第一次项目搜索

1. 打开侧边栏的 **Search** 视图。也可以打开命令面板，运行 **Search in Files**。
2. 在 **Search** 输入框中输入目标文字，例如一个函数名或错误信息。
3. 按 `Enter` 开始搜索。
4. 等待结果完成，查看匹配计数和按文件组织的结果。
5. 打开一条结果，在编辑器中查看对应文件和匹配位置。

**更改搜索词、匹配选项或文件范围后，需要再次按 Enter，或使用 Refresh search。** 输入框变化不会自动重搜，替换前务必让结果与当前条件一致。

使用中文输入法时，先确认候选文字，再按一次 `Enter` 提交搜索。

## 选择匹配方式

搜索框旁有三个选项：

- **Aa / Match Case**：强制区分大小写。
- **ab / Match Whole Word**：按完整词匹配，减少较长名称中的部分命中。
- **Use Regular Expression**（`.*`）：把搜索内容解释为正则表达式。

默认还开启了 `search.smartCase`：搜索词包含大写字母时，会自动区分大小写，即使 **Aa** 没有开启。如果需要始终忽略大小写，应关闭 **Aa**，并把 `search.smartCase` 设为 `false`，然后重新搜索。

先用普通文本确认结果，再开启正则表达式，能更容易发现表达式范围过大的问题。表达式报错时，按错误信息修正后重试。

## 限制要搜索的文件

1. 展开 **Search Details**。
2. 在 **files to include** 中填写要包含的路径模式。
3. 在 **files to exclude** 中填写要排除的路径模式。
4. 回到搜索框，按 `Enter` 重新搜索。

模式按工作区文件夹内的相对路径匹配，多个模式用逗号分隔。例如：

- 只搜索源码和文档：包含 `src/**, docs/**`
- 只搜索 TypeScript 文件：包含 `**/*.ts`
- 排除测试文件：排除 `**/*.test.ts`
- 排除依赖和构建产物：排除 `**/node_modules/**, **/dist/**`

`*` 用于匹配路径的一部分，`**` 可以跨越目录层级。搜索文本框使用的是文本或正则表达式；文件范围输入框使用的是路径模式，两者语法不同。

收起 **Search Details** 不会清空过滤条件。看到 **Search Details · filters active** 时，仍有文件范围条件生效；扩大范围需要展开并清除相应输入，再重新搜索。

## 检查和整理结果

先检查文件路径和高亮文本，再决定是否修改。搜索视图获得焦点时，按 `F4` 跳到下一个匹配项，按 `Shift+F4` 返回上一个匹配项。

结果操作菜单还可以帮助你阅读较多匹配项：

- **View as tree**：按目录结构展示结果。
- **Sort by match count**：优先查看匹配项较多的文件。
- **Copy All**：复制当前保留的结果，便于记录或比较。
- **Dismiss**：从当前结果中移除某条匹配项或文件；它不会删除磁盘文件，刷新后仍可能重新出现。

需要中断搜索时，使用 **Cancel Search**，或在搜索视图中按 `Esc`。已经返回的结果会保留，但只是本次搜索已完成的部分。

**出现 result limit reached 时，结果并不完整。** `search.maxResults` 默认是 `2000`，允许设置为 `100` 到 `5000` 的整数。优先缩小文件范围或使用更具体的关键词。停止或达到上限后，批量操作只会使用当前保留的结果。

## 预览并应用替换

建议首次批量修改使用预览，逐项检查替换后的内容。

1. 完成搜索，确认条件、文件范围和结果均正确。
2. 在 **Replace** 中输入替换文本。如果输入框被折叠，单击 **Toggle Replace** 展开。
3. 打开结果操作菜单，选择 **Preview replacement**。
4. 在预览中查看文件和文字变化，使用 **Open changes** 打开差异。
5. 取消勾选不需要的文件或具体替换项，只保留本次要修改的内容。
6. 检查选择后，单击 **Apply selected**。不想应用时选择 **Cancel**。
7. 返回搜索视图检查刷新后的结果，再检查受影响文件的内容和保存状态。

预览期间文件发生变化时，应用按钮可能不可用。取消预览，重新搜索，再生成新的替换预览。

## 选择其他替换范围

明确知道范围后，也可以使用以下操作：

- **Replace selected result**：焦点在一条匹配上时，只替换这一条；焦点在文件行上时，替换该文件当前保留的全部匹配。
- **Replace All**：替换当前结果中保留的所有匹配。确认对话框会显示匹配数和文件数，核对后再继续。

**Replace selected result** 依据当前焦点行决定范围，不是把所有多选行统一当作替换范围。需要精确选择多条修改时，使用 **Preview replacement** 中的复选框。

替换框为空表示删除匹配到的文本。使用 **Replace All** 前，检查空输入是否符合你的本意。

项目替换成功后会尝试保存受影响文件，并重新运行搜索。不要只用“原词消失了”判断完成；还应检查差异、保存错误和项目需要的测试。

## 使用捕获组和保留大小写

开启 **Use Regular Expression** 后，替换文本可以引用捕获组。例如，搜索 `(task)-(\d+)`，替换为 `$1_$2`，可以把 `task-12` 改成 `task_12`。先在预览中检查少量结果，再应用。

普通文本搜索模式下，`$1` 会作为普通文字使用，不会引用捕获组。

开启 **AB / Preserve Case** 可以按匹配文本保留大小写形式。例如，查找小写词、替换为另一个小写词时，全大写的匹配可以得到全大写的替换。项目命名混用多种大小写时，仍应逐项检查预览。

## 撤销与处理失败

需要撤销最近一次项目替换时，在搜索视图的结果操作菜单中选择 **Undo replacement**，再检查文件内容。该操作针对搜索视图保存的最近一次替换，不要依赖它恢复很久以前或重启前的修改。

**提示文件在搜索后发生变化。** 先保留或保存你希望留下的编辑，重新搜索，再确认新的匹配范围。Ash 会拒绝用过期位置直接替换。

**提示 Changes were applied, but saving failed。** 修改已经进入编辑内容，但至少一个文件未能保存。保留相关编辑器，按错误信息检查写入权限或连接，再手动保存并核对文件。不要在未确认状态前重复执行同一批替换。

**替换按钮不可用。** 等待搜索完成，并确认存在结果。执行中的搜索或替换会暂时禁用相关操作。

**没有结果或结果明显偏少。** 检查工作区、大小写和正则选项、文件过滤条件，以及搜索是否被取消或达到结果上限。未保存内容应先保存后重新检查。

**界面仍显示旧结果。** 修改条件后按 `Enter` 或选择 **Refresh search**。仅输入新的关键词不会更新已有结果。

## 常用命令与设置

- **Search in Files**：`workbench.action.findInFiles`
- **Search: Refresh**：`search.action.refreshSearchResults`
- **Search: Cancel Search**：`search.action.cancel`
- **Search: Clear Search Results**：`search.action.clearSearchResults`
- `search.smartCase`：是否根据搜索词中的大写字母决定大小写匹配，默认 `true`
- `search.maxResults`：搜索结果上限，默认 `2000`
- `search.showLineNumbers`：是否在搜索结果中显示行号，默认 `false`

**Preview replacement**、**Replace selected result** 和 **Undo replacement** 从搜索结果操作菜单使用。
