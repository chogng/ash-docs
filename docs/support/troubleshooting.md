# 排查常见问题

出现问题时，先确认失败发生在哪一步：应用启动、模型请求、工具执行，还是结果保存。保留第一次失败的信息，比连续重复同一操作更容易找到原因。

## 模型可以选择，但请求失败

模型列表可见和请求成功是两件事。先核对供应商、模型、凭据和端点，再查看请求实际返回的错误。

1. 确认选中的是你配置过的供应商和模型。
2. 检查该供应商的凭据是否有效，而不是只看模型开关。
3. 如果使用自定义端点，核对服务给出的地址和协议要求。
4. 先发送一条简短请求，确认基础连接，再重试原任务。

错误涉及服务额度、访问限制或模型不存在时，应按对应供应商的反馈处理，不要通过放宽文件权限来解决模型连接问题。

## 任务停在等待状态

查看会话是否在等待你批准某个操作，或回答一个问题。应在对应的交互界面处理请求，而不是反复发送相同任务。

如果连接刚中断，暂时没有新输出不一定表示任务失败。恢复后检查最新工具记录和实际文件状态。执行结果未知时，先确认操作是否已经发生，再决定是否重试，尤其是提交、发送、删除等外部操作。

参见[会话与任务](/docs/agents/sessions.md)和[权限与批准](/docs/configure/permissions.md)。

## 工具被拒绝或无法连接

区分这些情况：

- **未配置工具**：需要先完成工具或服务器配置。
- **连接或认证失败**：检查程序、地址、凭据和网络。
- **本次操作被拒绝**：检查请求的目标和权限范围。
- **调用失败或结果未知**：查看实际返回的信息和目标状态。

MCP 服务器显示启用，不代表连接和工具调用都已经成功。参见[连接 MCP 服务器](/docs/customize/mcp-servers.md)。

## 设置修改后没有生效

确认修改的是当前使用的 profile。通过 JSON 编辑设置时，需要保存文件，并处理语法、值校验或外部修改冲突。

图形设置中的“已配置”和 `@modified` 表示存在用户覆盖，即使保存值等于默认值也可能出现。恢复默认行为应使用重置。参见[调整设置](/docs/configure/settings.md)。

## 打开了浏览器界面，但 Agent 不能执行任务

Ash 源码提供仅界面和连接后端的浏览器开发模式。前者能用于界面开发，但不能据此判断真实 Agent 链路正常。

按当前源码的[前端指南](https://github.com/chogng/ash/blob/main/docs/frontend.md)检查启动模式、后端连接和模型配置。浏览器开发入口不等同于托管在线产品。

## 修改后测试仍然失败

先看测试输出中最早出现的有效错误。确认测试是在正确的目录、工具版本和环境中运行，并区分代码失败、依赖缺失和环境限制。

可以把明确的信息交给 Agent：

```text
这条测试命令失败了。请先解释最先失败的原因，区分代码问题和环境问题。
不要跳过测试或放宽断言。说明需要修改什么，再继续处理。
```

测试未运行或被环境阻止，不等于通过。跨平台行为也需要在对应平台验证。

## 提供一份容易复现的问题报告

准备以下信息：

- Ash 版本或源码提交，以及操作系统。
- 使用桌面应用还是 Ash Code。
- 从什么状态开始，按什么顺序操作。
- 你期望看到什么，实际发生了什么。
- 最小错误片段，以及问题是否每次出现。
- 必要截图，和你已经尝试过的方法。

分享前移除密钥、访问令牌、私有文件内容和不必要的个人目录。只保留解释问题需要的信息，不要直接上传整个配置目录或全部会话记录。
