# 排查常见问题

出现问题时，先确认失败发生在哪一步：应用启动、模型请求、工具执行，还是结果保存。保留第一次失败的信息，比连续重复同一操作更容易找到原因。

本文依据 2026 年 10 月 22 日的主分支源码；公开安装包的功能以实际发布版本为准。

## 模型可以选择，但请求失败

模型列表可见和请求成功是两件事。先核对供应商、模型、凭据和端点，再查看请求实际返回的错误。

1. 确认选中的是你配置过的供应商和模型。
2. 检查该供应商的凭据是否有效，而不是只看模型开关。
3. 如果使用自定义端点，核对服务给出的地址和协议要求。
4. 先发送一条简短请求，确认基础连接，再重试原任务。

错误涉及服务额度、访问限制或模型不存在时，应按对应供应商的反馈处理，不要通过放宽文件权限来解决模型连接问题。

## 任务停在等待状态

查看会话是否在等待你批准某个操作，或回答一个问题。应在对应的交互界面处理请求，而不是反复发送相同任务。

如果连接刚中断，暂时没有新输出不一定表示任务失败。恢复后检查最新工具记录和实际文件状态。执行结果未知时，先确认操作是否已经发生，再决定是否重试，尤其是提交、发送、删除等外部操作。

参见[会话与任务](/docs/agents/sessions.md)和[权限与批准](/docs/configure/permissions.md)。

## Agent Host 已连接，但工作区仍未恢复

窗口顶部的恢复横幅同时反映后端连接和工作区目录恢复。看到 **正在重新连接到 Agent Host…** 时等待恢复；若提示无法恢复连接或工作区，检查网络、后端和目录权限，再选择 **重新连接**（**Reconnect**）。

即使通信已经连接，目录恢复失败时提示仍会保留。重试会继续恢复工作区，不要只根据连接指示判断文件、终端或项目功能已可用。恢复后检查目录、任务记录和文件结果，避免重复发送或执行已经完成的操作。

若提示无法恢复且没有重连入口，按显示的错误检查后端或远程主机。修改权限后仍失败时，先保留未保存内容，再[复核当前工作区权限](/docs/configure/permissions.md#管理当前工作区的权限)，不要用扩大授权代替排查连接故障。

## 工具被拒绝或无法连接

区分这些情况：

- **未配置工具**：需要先完成工具或服务器配置。
- **连接或认证失败**：检查程序、地址、凭据和网络。
- **本次操作被拒绝**：检查请求的目标和权限范围。
- **调用失败或结果未知**：查看实际返回的信息和目标状态。

MCP 服务器显示启用，不代表连接和工具调用都已经成功。参见[连接 MCP 服务器](/docs/customize/mcp-servers.md)。

## 设置修改后没有生效

确认修改的是当前使用的 profile，以及预期的用户、工作区或文件夹范围；设置了 `@lang:` 筛选时，也检查语言目标。通过 JSON 编辑设置时，需要保存文件，并处理语法、值校验或外部修改冲突。

图形设置中的“已配置”和 `@modified` 表示所选范围中存在覆盖，即使保存值等于默认值也可能出现。重置只移除所选范围和语言的覆盖，其他配置层仍可能影响结果。参见[调整设置](/docs/configure/settings.md)。

## 托管设置刷新失败

在 **Codex 审查** 设置页查看托管设置的最近尝试、最近成功刷新时间和错误提示，再选择 **刷新托管设置**。这项操作使用主 GitHub 账户，切换仓库访问账户不会替换策略账户。

认证失败时重新连接 GitHub；限流时等待后重试；权限或客户端兼容性错误请联系管理员。若状态显示 **已保留之前接受的设置**，旧策略仍可能生效，不能把刷新失败当成限制解除。详见[刷新账户的托管设置](/docs/configure/settings.md#刷新账户的托管设置)。

## 听写按钮消失或模型设置冲突

* 按钮消失：检查 `dictation.enabled` 和 `dictation.showButton`。后者只控制消息输入框的按钮，隐藏后仍可使用听写命令。
* 本地模型不可用：在 **语音输入** 设置中检查模型是否已安装，并通过 **使用模型** 选择它。只填写模型包 ID 不会完成安装。
* 新旧设置冲突：将需要的值保留在 `dictation.model` 中，移除 `dictation.localModel`，再保存用户设置 JSON。发生冲突时，Ash 不会替你决定保留哪个模型。

## 工作区目录没有更新

本地多根工作区的配置文件保存后会自动更新目录。没有变化时，检查路径是否存在、是否取得目录授权，以及配置是否有效。移除根或新增嵌套根会改变未保存文件的归属时，先保存或还原这些文件，再次保存工作区配置以重试。

不要把目录顺序当作终端执行目录。新终端使用活动文件所属的根，不能确定时会请你选择；已有终端仍绑定原来的根。完整流程见[项目与工作区](/docs/editing/workspaces.md)。

## Rust 没有补全，或语言服务器设置打不开

先检查语言服务器是否启用，以及状态栏或对应输出通道中的错误。Rust 的 `rust-analyzer` 与 `cargo`、`rustc` 分开准备，服务器可用不代表工具链完整。

填写自定义程序路径前，确认它是后端主机上实际存在的绝对可执行路径。单个服务器路径无效或安装失败时，仍可打开设置修正路径、停用服务器或恢复默认配置。Rust 的环境变量覆盖同时用于可用性探测和启动；选择工具链后仍需确认该工具链可用。配置范围、重复语言路由和日志入口见[配置语言服务器](/docs/configure/language-servers.md)。

## Windows 系统授权保存被取消或结果无法确认

保存受保护文件时，如果提供 **Retry with administrator permission**，可按需要选择并处理 Windows 系统授权提示。取消授权后，尚未保存的修改仍保留在编辑器中。

如果提示保存结果无法确认，先保留当前编辑内容的副本，再重新读取或核对磁盘文件，确认实际结果后再决定是否重试。失败提示不一定表示磁盘完全没有写入；不要直接关闭未保存的编辑器或反复覆盖文件。

## 桌面窗口无响应，或关闭和重载卡住

桌面窗口没有响应，或关闭、重新加载窗口的准备过程超过 30 秒时，会出现原生恢复提示。这不是 Agent 或终端任务的运行时限，也不表示导致卡住的问题已经解决。此入口适用于桌面应用，不是浏览器页面的恢复操作。

* **继续等待**（**Keep Waiting**）：优先选择此项，让尚未完成的保存或关闭步骤继续。它不会取消原操作；操作完成后提示会消失，仍未完成时稍后会再次提示。
* **重新打开**（**Reopen**）：为同一工作区创建替代窗口。这是应急恢复，不等同于普通的 **Reload Window**。
* **关闭**（**Close**）：直接关闭当前窗口，不再等待正常关闭步骤。

窗口中的页面进程已经崩溃或退出时，只提供 **重新打开**和 **关闭**。应急重新打开或关闭都可能丢失尚未备份的更改，不应当作正常保存退出。恢复后先检查文件、会话和终端的实际状态，再决定是否重试操作；终端特别需要注意[应急恢复与普通重载的区别](/docs/terminal/basics.md#重新加载窗口)。

## 重新加载后终端没有恢复

桌面窗口重载与退出应用不同。默认开启的 `terminal.integrated.enablePersistentSessions` 会尝试保留受支持的普通 Shell，但依赖终端宿主、原进程和有效重连凭据。本地终端在原窗口存活连接仍有效时可以跨 Ash 后端重启恢复；SSH 终端仍受有限重连租约限制。终端宿主退出、凭据失效或扩展自供 PTY 都可能阻止恢复。

先检查进程和实际文件结果，再决定是否重新启动终端。重新启动创建的是新进程，不会续跑旧命令。见[终端重载与连接恢复](/docs/terminal/basics.md#重新加载窗口)。

## 找不到通话，或成员打不开文档

当前 Code 工作台从侧栏 **协作**（**Collaboration**）进入 **频道** 和 **通话**。也可以运行 **Open Calls**。没有入口时先核对使用的版本、工作台和连接状态。

频道共享笔记继承所在空间的成员权限；通话中链接的独立文档仍有自己的邀请权限。加入通话或收到文档链接，不代表已经获得该文档权限。分别参见[协作频道与共享笔记](/docs/editing/channels.md)和[通话中的共享文档](/docs/editing/call-documents.md)。

## 截图无法开始或没有加入聊天

先从命令面板运行 **聊天：添加截图**。若这样能开始，而快捷键不能使用，检查按键绑定和 `screenshot.globalShortcut`，并处理全局快捷键注册通知。

macOS 要求录屏权限时，按截图时显示的指引打开系统设置，为提示中的当前应用程序授权。开发实例与打包后的 Ash 可能使用不同的应用身份；不要只检查另一个版本。系统要求重启应用时，先保存工作，再退出并重新打开。

截图中的 **复制** 和 **保存** 不会添加聊天附件。要加入草稿，选择 **加入聊天**，再回到输入框检查附件；发送仍由你完成。取消截图会返回原草稿。完整流程参见[截图与标注](/docs/editing/screenshots.md)。

## 打开了浏览器界面，但 Agent 不能执行任务

Ash 源码提供仅界面和连接后端的浏览器开发模式。前者能用于界面开发，但不能据此判断真实 Agent 链路正常。

按当前源码的[前端指南](https://github.com/chogng/ash/blob/main/docs/frontend.md)检查启动模式、后端连接和模型配置。浏览器开发入口不等同于托管在线产品。

## 浏览器页面提示更新，或找不到检查更新

部署的 Web 构建接入更新服务后，可从 **帮助 → 检查更新...** （**Help → Check for Updates...** ）或命令面板检查新部署。工作台恢复后也会检查一次；检测到更新时，选择通知中的 **重新加载以更新**（**Reload to Update**）。重新加载经过现有关闭检查和未保存内容保护，请按提示处理尚未保存的工作。

本地开发服务器没有部署版本标识，不会自动检查部署更新。直接嵌入工作台的页面若未提供更新服务，检查更新命令不可用。普通 Web 工作台和 Agents 的 Web 入口都支持已构建部署的更新检查，但这不表示仓库提供公开托管服务。

若出现 **无法检查更新**，先检查站点网络和部署是否完整。内置检查读取同源的版本清单，请求最长等待 10 秒。站点维护者需要把页面、资源和 `web-version.json` 一起发布；不要仅凭没有更新通知就判断页面已是最新版。

## 修改后测试仍然失败

先看测试输出中最早出现的有效错误。确认测试是在正确的目录、工具版本和环境中运行，并区分代码失败、依赖缺失和环境限制。

可以把明确的信息交给 Agent：

```text
这条测试命令失败了。请先解释最先失败的原因，区分代码问题和环境问题。
不要跳过测试或放宽断言。说明需要修改什么，再继续处理。
```

测试未运行或被环境阻止，不等于通过。跨平台行为也需要在对应平台验证。

## 用输出日志定位问题

打开 **输出**（Output）面板，选择与失败有关的通道。桌面应用还可从命令面板运行 **输出：打开已保存的日志…**，选择当前日志、保留的历史日志或轮转日志。列表会区分 **实时** 和 **已保存**；实时来源继续接收新输出。

排查后端时，区分 **本地 App Server** 和 **App Server 连接**：前者是后端进程日志，后者记录连接状态。浏览器开发界面没有桌面应用的已保存日志入口。

### 区分显示筛选和记录级别

* **最低显示级别**、文本和类别筛选：只隐藏当前视图中的记录，不改变来源记录哪些消息。
* **设置…记录级别**：更改指定来源之后记录的消息。仅支持该操作的来源显示这个菜单；历史日志和原始文件来源没有它。
* **设置工作台记录级别**：作用于工作台日志，不会统一改变同一文件里其他独立日志来源的级别。

需要更多诊断信息时，先为对应来源调整记录级别，再重现问题。放宽显示筛选无法找回从未记录的消息。完成排查后，将临时调整的记录级别恢复。

需要让后续窗口和新日志来源继续采用该级别时，在记录级别菜单中选择 **设为默认**（**Set As Default**）。扩展通道只保存该扩展的默认值；其他通道保存通用默认值。现有来源只有仍使用旧默认值时才跟随更新，显式或独立调整的级别会保留。历史日志和没有记录级别控制的来源不能设置默认值。

默认值保存到当前界面 profile 的启动配置，默认级别为 `info`；桌面启动参数 `--log` 或 `--verbose` 可以在启动时覆盖它。保存失败时先处理启动配置中未保存的编辑、语法或保存冲突，不要把当前临时级别当成已经保存。

### 清空、跟随和导出

**清空输出** 只清空通道当前显示的内容，不删除或截断原始日志文件。实时日志会从当前读取位置继续；重新加载后，保留文件中的记录可能再次出现。

**暂停跟随输出** 只停止跟随新增内容，不停止任务或记录。需要回到最新内容时，选择 **跟随新增输出**。默认开启的 `output.smartScroll.enabled` 还会在主光标移到较早行时暂停自动滚动，在移到最后一行时恢复。

出现日志轮转、截断或读取上限提示时，说明较早输出有缺口，不代表这段时间没有错误。可在已保存日志中检查仍保留的轮转文件。

> [!IMPORTANT]
> **导出输出…** 导出当前通道保留的全部文本，不受面板的显示筛选限制。分享前打开导出文件检查并脱敏，不能用隐藏某些行代替删除敏感内容。

## 导出 Agent 诊断包

需要一起检查应用日志和会话证据时，可以导出诊断 ZIP：

1. 打开要检查的聊天，确认当前会话和 Thread。
2. 在命令面板运行 **开发人员：导出 Agent Host 调试日志…**（**Developer: Export Agent Host Debug Logs…**，`workbench.action.chat.exportAgentHostDebugLogs`）。
3. 等待下载 `ash-agent-host-debug-logs.zip`。导出期间可在进度通知中取消。
4. 解压并查看 `manifest.json`，确认收集范围以及缺失、截断或读取失败的来源，再查看相关文件。

诊断包会尝试收集当前窗口、本地宿主及后端日志、已保留的日志通道，并加入所选会话已有的执行记录，以及当前聊天和已记录子任务可读取的请求正文。没有活动聊天时，不包含会话证据；没有桌面文件日志的 Web 环境也可能缺少相应来源。部分来源失败时仍可生成不完整的诊断包，请以清单为准。

导出不会开启详细记录，也不能补回过去未记录的正文。单次包最大 64 MiB，单文件最大 16 MiB，文件数量和分页也有上限；下载成功不表示全部历史都已收集。只想离线查看会话时，使用 [Agent 调试日志](/docs/agents/trace.md)中的 **导出 Trace**。诊断 ZIP 不能直接用于 **导入 Trace**。

> [!IMPORTANT]
> 诊断包可能包含私有对话、工具结果、路径和请求正文。它不按面板显示筛选脱敏。分享前检查并移除敏感内容，确认接收人可以看到保留下来的信息。

## 提供一份容易复现的问题报告

准备以下信息：

- Ash 版本或源码提交，以及操作系统。
- 使用桌面应用还是 Ash Code。
- 从什么状态开始，按什么顺序操作。
- 你期望看到什么，实际发生了什么。
- 最小错误片段，以及问题是否每次出现。
- 必要截图，和你已经尝试过的方法。

分享前移除密钥、访问令牌、私有文件内容和不必要的个人目录。只保留解释问题需要的信息，不要直接上传整个配置目录或全部会话记录。
