# 排查常见问题

出现问题时，先确认失败发生在哪一步：应用启动、模型请求、工具执行，还是结果保存。保留第一次失败的信息，比连续重复同一操作更容易找到原因。

## 模型可以选择，但请求失败

模型列表可见和请求成功是两件事。先核对供应商、模型、凭据和端点，再查看请求实际返回的错误。

1. 确认选中的是你配置过的供应商和模型。
2. 检查该供应商的凭据是否有效，而不是只看模型开关。
3. 如果使用自定义端点，核对服务给出的地址和协议要求。
4. 先发送一条简短请求，确认基础连接，再重试原任务。

错误涉及服务额度、访问限制或模型不存在时，应按对应供应商的反馈处理，不要通过放宽文件权限来解决模型连接问题。

## 任务停在等待状态

查看会话是否在等待你批准某个操作，或回答一个问题。应在对应的交互界面处理请求，而不是反复发送相同任务。

如果连接刚中断，暂时没有新输出不一定表示任务失败。恢复后检查最新工具记录和实际文件状态。执行结果未知时，先确认操作是否已经发生，再决定是否重试，尤其是提交、发送、删除等外部操作。

参见[会话与任务](/docs/agents/sessions.md)和[权限与批准](/docs/configure/permissions.md)。

## 工具被拒绝或无法连接

区分这些情况：

- **未配置工具**：需要先完成工具或服务器配置。
- **连接或认证失败**：检查程序、地址、凭据和网络。
- **本次操作被拒绝**：检查请求的目标和权限范围。
- **调用失败或结果未知**：查看实际返回的信息和目标状态。

MCP 服务器显示启用，不代表连接和工具调用都已经成功。参见[连接 MCP 服务器](/docs/customize/mcp-servers.md)。

## 设置修改后没有生效

确认修改的是当前使用的 profile。通过 JSON 编辑设置时，需要保存文件，并处理语法、值校验或外部修改冲突。

图形设置中的“已配置”和 `@modified` 表示存在用户覆盖，即使保存值等于默认值也可能出现。恢复默认行为应使用重置。参见[调整设置](/docs/configure/settings.md)。

## 听写按钮消失或模型设置冲突

* 按钮消失：检查 `dictation.enabled` 和 `dictation.showButton`。后者只控制消息输入框的按钮，隐藏后仍可使用听写命令。
* 本地模型不可用：在 **语音输入** 设置中检查模型是否已安装，并通过 **使用模型** 选择它。只填写模型包 ID 不会完成安装。
* 新旧设置冲突：将需要的值保留在 `dictation.model` 中，移除 `dictation.localModel`，再保存用户设置 JSON。发生冲突时，Ash 不会替你决定保留哪个模型。

## 截图无法开始或没有加入聊天

先从命令面板运行 **聊天：添加截图**。若这样能开始，而快捷键不能使用，检查按键绑定和 `screenshot.globalShortcut`，并处理全局快捷键注册通知。

macOS 要求录屏权限时，按截图时显示的指引打开系统设置，为提示中的当前应用程序授权。开发实例与打包后的 Ash 可能使用不同的应用身份；不要只检查另一个版本。系统要求重启应用时，先保存工作，再退出并重新打开。

截图中的 **复制** 和 **保存** 不会添加聊天附件。要加入草稿，选择 **加入聊天**，再回到输入框检查附件；发送仍由你完成。取消截图会返回原草稿。完整流程参见[截图与标注](/docs/editing/screenshots.md)。

## 打开了浏览器界面，但 Agent 不能执行任务

Ash 源码提供仅界面和连接后端的浏览器开发模式。前者能用于界面开发，但不能据此判断真实 Agent 链路正常。

按当前源码的[前端指南](https://github.com/chogng/ash/blob/main/docs/frontend.md)检查启动模式、后端连接和模型配置。浏览器开发入口不等同于托管在线产品。

## 修改后测试仍然失败

先看测试输出中最早出现的有效错误。确认测试是在正确的目录、工具版本和环境中运行，并区分代码失败、依赖缺失和环境限制。

可以把明确的信息交给 Agent：

```text
这条测试命令失败了。请先解释最先失败的原因，区分代码问题和环境问题。
不要跳过测试或放宽断言。说明需要修改什么，再继续处理。
```

测试未运行或被环境阻止，不等于通过。跨平台行为也需要在对应平台验证。

## 用输出日志定位问题

打开 **输出**（Output）面板，选择与失败有关的通道。桌面应用还可从命令面板运行 **输出：打开已保存的日志…**，选择当前日志、保留的历史日志或轮转日志。列表会区分 **实时** 和 **已保存**；实时来源继续接收新输出。

排查后端时，区分 **本地 App Server** 和 **App Server 连接**：前者是后端进程日志，后者记录连接状态。浏览器开发界面没有桌面应用的已保存日志入口。

### 区分显示筛选和记录级别

* **最低显示级别**、文本和类别筛选：只隐藏当前视图中的记录，不改变来源记录哪些消息。
* **设置…记录级别**：更改指定来源之后记录的消息。仅支持该操作的来源显示这个菜单；历史日志和原始文件来源没有它。
* **设置工作台记录级别**：作用于工作台日志，不会统一改变同一文件里其他独立日志来源的级别。

需要更多诊断信息时，先为对应来源调整记录级别，再重现问题。放宽显示筛选无法找回从未记录的消息。完成排查后，将临时调整的记录级别恢复。

### 清空、跟随和导出

**清空输出** 只清空通道当前显示的内容，不删除或截断原始日志文件。实时日志会从当前读取位置继续；重新加载后，保留文件中的记录可能再次出现。

**暂停跟随输出** 只停止跟随新增内容，不停止任务或记录。需要回到最新内容时，选择 **跟随新增输出**。默认开启的 `output.smartScroll.enabled` 还会在主光标移到较早行时暂停自动滚动，在移到最后一行时恢复。

出现日志轮转、截断或读取上限提示时，说明较早输出有缺口，不代表这段时间没有错误。可在已保存日志中检查仍保留的轮转文件。

> [!IMPORTANT]
> **导出输出…** 导出当前通道保留的全部文本，不受面板的显示筛选限制。分享前打开导出文件检查并脱敏，不能用隐藏某些行代替删除敏感内容。

## 提供一份容易复现的问题报告

准备以下信息：

- Ash 版本或源码提交，以及操作系统。
- 使用桌面应用还是 Ash Code。
- 从什么状态开始，按什么顺序操作。
- 你期望看到什么，实际发生了什么。
- 最小错误片段，以及问题是否每次出现。
- 必要截图，和你已经尝试过的方法。

分享前移除密钥、访问令牌、私有文件内容和不必要的个人目录。只保留解释问题需要的信息，不要直接上传整个配置目录或全部会话记录。
